## 설치 파일을 다시 돌리지 않는다 (2026-10-06)

운영 서버의 함수와 보기는 날짜별 파일이 차례로 덮어쓴 결과입니다. 옛 파일을 다시 돌리면 그 파일이 만든 옛 함수와 보기로 돌아가서 모임 글 검사, 참석 수, 끝나는 시간, 지도가 한꺼번에 사라집니다.

- 그래서 `setup_all.sql`, `site_features*.sql`, 2026-10-05 이전의 날짜별 파일(함수나 보기를 만드는 것)은 첫 줄에서 서버에 끝나는 시간 판(`bung_end`)이 있는지 보고, 있으면 '이 서버에는 더 새로운 판이 적용되어 있습니다' 로 멈춥니다. 아무것도 바뀌지 않습니다.
- 돌려도 되는 것: `status.sql`, `backup.sql`, `set_admin_password.sql`, `2026-10-06-rate-limit.sql`, 운영 대시보드 두 파일(`2026-09-27-ops-store.sql`, `2026-09-28-ops-sheet.sql`), 그리고 이 날짜 뒤에 새로 나오는 파일. 단 `2026-10-09-memberbot.sql` 을 돌린 뒤에는 같은 날의 `members` 와 `midjoin-botctl` 은 돌리지 않습니다(첫 줄에서 멈춤). 보강 1쪽(`2026-10-03-bung-attend-5.sql`)과 끝나는 시간 2쪽(`2026-10-05-bung-end-2.sql`)도 `2026-10-09-midjoin-botctl.sql` 뒤에는 첫 줄에서 멈춥니다(돌리면 참석, 참석 취소, 같은 시간대 검사가 옛 판으로 돌아가므로).
- 무엇을 고치거나 되돌릴 일이 있으면 옛 파일을 돌리지 말고 새 날짜의 파일을 받습니다.

- 기존 가게·한줄평은 바뀌지 않습니다. 좌표는 비어 있으므로 실행 직후에는 지도에 핀이 없습니다.

## 방문 횟수 카운터 (2026-09-21)

`sql/2026-09-21-visit-hits.sql` 을 SQL Editor 에 붙여넣고 **Run** 하세요. 다시 실행해도 안전합니다.

- 상단 내비의 **오늘·누적**이 '기기당 하루 1회'가 아니라 **링크를 타고 사이트에 들어올 때마다 +1** 로 셉니다. 같은 사람이 세 번 들어오면 3. 같은 탭 안에서 홈→맛집으로 옮기거나 새로고침하는 건 한 번의 입장이라 더 세지 않습니다. 새 표 `site_visit_counts`(날짜별 횟수)와 함수 `visit_hit()` 이 생깁니다.
- 지금까지의 기록(`site_visit_log`)은 날짜별 합으로 새 표에 옮겨 시작값이 되므로 누적이 0 으로 돌아가지 않습니다. 옛 표는 더 쓰지 않고, `2026-10-16-privacy-cleanup.sql` 로 지웁니다.
- 옛 함수 `visit_ping` 은 남겨 둡니다 — 브라우저에 옛 스크립트가 남아 있어도 같은 셈이 되고, 새 스크립트는 탭 안에서 페이지를 옮길 때 이 함수의 읽기 전용 경로(`p_count=false`)로 숫자만 받아 갑니다. 기기 키는 더 이상 저장하지 않습니다.

확인: 파일 맨 아래 확인 쿼리에서 `days`(기록이 있는 날짜 수)와 `total`(누적) 한 줄이 나오면 끝입니다. `days` 는 오늘 횟수가 아닙니다. 오늘 횟수는 `select day, hits from site_visit_counts order by day desc limit 5;` 의 맨 윗줄입니다.
