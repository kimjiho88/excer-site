## 2. 콘텐츠 종류별 정리 양식 (요약 — 전문은 CONTENT_FORMAT.md)

- 맛집: 식당명 · 지역(+위치 메모) · 종류 · 1인 가격 · 추천 메뉴 · 한줄평 · 방문 팁 · 작성자 · 등록일/방문일 · 지도. 목록은 1~6 순서, 상세는 기본 정보→추천 메뉴→방문 후기→방문 팁→위치와 지도→작성 정보.
- 소식: 공지(핵심 안내·적용 대상·적용일/종료일·필요한 행동·상세) / 모임 모집(모임명·날짜·시간·장소·인원·비용·모임장·신청 방법·준비물·상태) / 모임 후기(활동·날짜·장소·본문·링크) / 정보(핵심 내용·출처·링크·유효 기간) / 자유(제목·본문). 저장은 `site_posts.meta`, 서버 정리기가 아는 키만 남김.

## 4. 새 등록·수정 흐름

- 맛집 등록/수정: 식당 이름 → 지역·종류 → 주소 또는 위치 → 지도 링크 → 1인 가격·메모 → (수정 시) 영업 종료 → 작성 정보 → 목록 미리보기. 오류는 항목 아래, 서버 오류(같은 식당·비밀번호·링크)도 해당 항목에.
- 한줄평 등록/수정: 한줄평(필수) → 추천 메뉴 → 방문 팁 → 방문일 → 1인 금액 → 다시 가고 싶음 → 작성 정보 → 상세 미리보기. 수정은 정리본을 미리 채움. 서버가 이전 형식이면 메뉴·팁 칸을 닫고 안내.
- 소식 글쓰기/수정: 글 종류 → (유형별 항목) → 제목(모집은 모임명) → 내용 → 작성 정보 → 목록 행 + 항목 표 미리보기. 수정도 같은 모달, 항목이 채워짐.
- 우선순위: 작성자가 수정한 서버 값 > 정리본(원문이 같을 때만) > 원문.

## 5. 검증 기록

- 기능: contenttest.js 44건, a11ytest.js 24건, uitest.js 33건, settle-test.js 9건, nametest.js 7건, guidetest.js 6건, reporttest.js 13건, footcheck.js, curate-check.js — 전부 통과, JS 오류 없음.
- 화면: 390 / 768 / 1440 가로 넘침 없음(전 페이지). 상태: 빈 목록·불러오기 실패·검색 결과 없음·이전 형식 서버·긴 후기·한 문장 후기·가격 없음·애매한 지역·추천+아쉬움 후기·정보 부족 모임 글·긴 공지·글 2개 목록.
- 서버 SQL: 로컬 PostgreSQL 16 에 setup_all → bung-fields → places 1~4 → slash → content-format 순으로 적용. 두 번 실행 안전, 함수 동작(잘못된 링크 제거, 자유 글 meta 삭제, 옮겨온 한줄평은 운영진만 수정) 확인.
- 직접 확인하지 못한 것: 실서비스 데이터(프록시 차단), 카카오톡 인앱 브라우저·실기기 공유 창, Supabase 실제 적용.

## 6. 운영자가 확인할 사실·정책·콘텐츠

1. `sql/2026-09-24-content-format.sql` 을 실행해야 추천 메뉴·방문 팁·유형별 항목이 저장됩니다(README 참고). 실행 전에도 사이트는 동작합니다.
2. 정리본(data/places-curated.json)의 문장이 작성자 뜻과 다르다고 판단되면 항목을 고치거나 지우면 됩니다(지우면 원문 표시).
3. 홈 도입 문장 "오픈채팅으로 만나는 동네 커뮤니티입니다. 모임에서 함께 다녀온 식당과 모임 소식을 모았습니다."가 실제 운영과 맞는지.
4. 소식의 '모집 상태'는 모임장이 직접 바꿉니다. 인원으로 자동 마감하지 않습니다(이전 정책 유지).
5. 영업 종료 식당은 삭제 대신 '현재 영업 종료' 표시가 원칙입니다.
