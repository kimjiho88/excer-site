## 2. 콘텐츠 종류별 정리 양식 (요약 — 전문은 CONTENT_FORMAT.md)

- 맛집: 식당명 · 지역(+위치 메모) · 종류 · 1인 가격 · 추천 메뉴 · 한줄평 · 방문 팁 · 작성자 · 등록일/방문일 · 지도. 목록은 1~6 순서, 상세는 기본 정보→추천 메뉴→방문 후기→방문 팁→위치와 지도→작성 정보.
- 소식: 공지(핵심 안내·적용 대상·적용일/종료일·필요한 행동·상세) / 모임 모집(모임명·날짜·시간·장소·인원·비용·모임장·신청 방법·준비물·상태) / 모임 후기(활동·날짜·장소·본문·링크) / 정보(핵심 내용·출처·링크·유효 기간) / 자유(제목·본문). 저장은 `site_posts.meta`, 서버 정리기가 아는 키만 남김.

## 4. 새 등록·수정 흐름

- 맛집 등록/수정: 식당 이름 → 지역·종류 → 주소 또는 위치 → 지도 링크 → 1인 가격·메모 → (등록 시) 첫 한줄평(선택: 한줄평·추천 메뉴·방문 팁·방문일·1인 금액·재방문) / (수정 시) 영업 종료 → 작성 정보 → 목록 미리보기(첫 한줄평도 목록 규칙 그대로). 저장은 place_create → (한줄평이 있으면) place_note_create 한 번. 한줄평 없이 메뉴·팁만 적으면 한줄평을 요구(가짜 후기 문장 없음). 오류는 항목 아래, 서버 오류(같은 식당·비밀번호·링크·방문일)도 해당 항목에.
- 한줄평 등록/수정: 한줄평(필수) → 추천 메뉴 → 방문 팁 → 방문일 → 1인 금액 → 다시 가고 싶음 → 작성 정보 → 상세 미리보기. 수정은 정리본을 미리 채움. 서버가 이전 형식이면 메뉴·팁 칸을 닫고 안내.
- 소식 글쓰기/수정: 글 종류 → (유형별 항목) → 제목(모집은 모임명) → 내용 → 작성 정보 → 목록 행 + 항목 표 미리보기. 수정도 같은 모달, 항목이 채워짐.
- 우선순위: 작성자가 수정한 서버 값 > 정리본(원문이 같을 때만) > 원문.
