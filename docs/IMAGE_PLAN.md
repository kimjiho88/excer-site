# 탭별 이미지 기획과 생성 프롬프트 (챗GPT용)

홈 대표 그림(가을 모닥불) 한 장으로 잡힌 화풍을 사이트 전체로 넓히는 계획입니다. 이미지는 챗GPT에 커버 그림을 첨부해 같은 톤으로 만들고, 파일이 들어오면 자리를 여는 순서로 갑니다. 규격·표시 규칙은 `docs/IMAGE_SPEC.md`, 색 체계는 `assets/site.css` 토큰이 기준입니다.

**진행 상태(2026-09-21)**: 1차 16장 전부 도착·적용. 안내·맛집 배너, 소식·통계·정산(정산 확인 공용) 스팟, 오늘 뭐 먹지, 소식·맛집·통계 빈 상태, 오프라인이 화면에 붙었고, 홈 계절 6장은 웹용 파일까지 만들어 두었습니다(가을 유지, 교체는 수동). 공유 미리보기는 안내·맛집·소식·통계·정산 5장을 조립해 연결했습니다. 적용 규격은 `IMAGE_SPEC.md` 4~8절. 실제 생성된 정사각형은 1024 가 아니라 1254 × 1254 였고 그대로 줄여 썼습니다. 8차에서 배너·스팟이 전면 커버로 커졌습니다(`IMAGE_SPEC.md` 9절).

**2차(본문 그림) — 생성 대기**: 커버는 채웠지만 목록·단계·규칙 본문은 아직 글자뿐입니다. 반복되는 자리에 넣을 미니 스팟 세트 34장의 목록과 프롬프트를 **7절**에 적었습니다.

**재검토(2026-09-21 저녁) — 화풍을 바꿉니다**: 1차 16장을 다시 보니 장면 그림과 스팟 그림이 서로 다른 화풍이고, 장면은 '다섯 명이 나란히 웃는' 같은 구도의 반복이라 사이트가 한 벌로 읽히지 않습니다. 진단과 새 화풍(스타일 카드), 시험 6장, 다시 만드는 순서를 **8절**에 적었습니다. **4절 4-0 의 기준 메시지와 7-3 의 5번 항목은 8절의 스타일 카드로 대체**합니다. 4절·7절의 장면 설명(무엇을 그릴지)은 그대로 씁니다.

## 1. 기획 검토 — 어디에 두고 어디에 두지 않나

이미지는 세 가지 일만 합니다. 이 셋에 들지 않으면 두지 않습니다.

| 역할 | 어디 | 왜 |
|---|---|---|
| **분위기** — 이 방이 어떤 곳인지 3초 안에 전달 | 홈 대표 그림, 이용 안내·맛집 머리 배너 | 글보다 빠르고, 채팅에 붙는 미리보기 카드가 된다 |
| **표지판** — 이 탭이 무엇을 하는 곳인지 | 통계·정산·소식 머리의 작은 스팟 그림 | 탭마다 다른 얼굴이 생겨 "같은 사이트의 다른 방"으로 읽힌다 |
| **빈 자리 채움** — 데이터가 없을 때 첫 행동 유도 | 소식·맛집·통계의 빈 상태, 오프라인 페이지 | 빈 화면이 "고장"이 아니라 "아직"으로 읽힌다 |

두지 않는 곳: 차트·표·목록 옆(숫자와 경쟁), 도해(`.flow`, 레인)와 콜아웃 안(이미 도해가 그림 역할), 글쓰기·등록 폼, 정산 결과 카드(이미지로 저장되는 영역이라 무거워짐), 모든 섹션 제목 옆 장식.

## 2. 화풍 기준 — 커버 그림에 맞춘다

커버 그림(가을 모닥불)의 특징을 그대로 잇습니다. 새 그림이 이 조건을 벗어나면 다시 뽑습니다.

- **한국 웹툰풍 디지털 일러스트**. 깨끗한 선, 부드러운 셀 셰이딩에 회화적인 빛. 실사·3D·수채화 아님.
- **따뜻한 빛이 주인공**. 등불·창문·모닥불·석양처럼 화면 안에 광원이 하나 있고, 그 빛이 인물과 사물을 감싼다.
- **색**. 그림 안은 주황·빨강·남색이 자유롭지만, 사이트 바탕(크림 `#F7F5EF`)과 보라(`#4B2A82`)·녹슨 주황(`#A9502D`)·황토(`#7E5F25`) 옆에 놓여도 튀지 않아야 한다. 형광색·쨍한 하늘색·민트 금지.
- **사람**. 20대 후반~30대, 다섯 명 안팎, 웃거나 이야기하는 중. 특정 실존 인물·연예인 닮음 금지. 얼굴 클로즈업 금지(생성 결함이 얼굴·손에서 나온다).
- **글자 없음**. 간판·메뉴판·휴대폰 화면·책 표지 어디에도 글자가 없어야 한다. 생성된 글자는 항상 깨진다. 간판은 빈 판이나 그림 기호로.
- **한국 동네 배경**. 골목 식당, 포장마차, 한강 공원, 벚꽃길, 아파트 창문 불빛. 서양식 다이너·유럽 광장 아님.
- **브랜드·로고 없음**. 카카오·특정 식당·맥주 상표가 보이면 안 된다.

### 다섯 친구 — 홈 계절 그림에서 이어 쓰는 인물 설정

커버 그림의 다섯 명을 다른 계절에도 같은 사람으로 둡니다. 챗GPT가 얼굴을 완전히 같게 내지는 못하므로 옷과 머리로 알아보게 합니다. 홈 계절 그림에만 쓰고, 배너·스팟에는 필요 없습니다.

| B | 짧은 갈색 머리, 진녹색 재킷에 흰 후드 |

## 3. 규격 요약

챗GPT는 세 가지 크기만 냅니다. 가로 1536×1024(3:2), 세로 1024×1536(2:3), 정사각 1024×1024. 4:5 와 4:3 은 이 중 하나로 받아서 잘라 씁니다. 프롬프트에 "위아래(또는 좌우) 끝은 잘라낼 것"이라고 미리 알려 두면 중요한 것이 끝에 놓이지 않습니다.

| 종류 | 챗GPT에 요청할 크기 | 잘라 쓰는 방법 | 웹용 파일 | 표시 | 용량 상한 |
|---|---|---|---|---|---|
| 홈 계절 장면 3:2 | 가로 1536×1024 | 그대로 | 1440×960·720×480 | 지금 가을 그림과 같은 자리·규칙 | 300 KB |
| 홈 계절 장면 4:5 | 세로 1024×1536 | 위아래 합쳐 256px 잘라 1024×1280 | 800×1000·400×500 | 모바일 340px 폭 | 200 KB |
| 머리 배너(안내·맛집) 3:2 | 가로 1536×1024 | 그대로 | 1440×960·720×480 | PC: 제목 오른쪽 열. 모바일: 제목 아래 화면 폭(350×233). 인물이 작아야 모바일에서도 읽힌다 | 300 KB / 100 KB |
| 스팟(통계·정산·소식·오늘 뭐 먹지·오프라인) 1:1 | 정사각 1024×1024 | 그대로 | 480×480·240×240 | 96~120px 원 또는 둥근 네모 | 40 KB |
| 빈 상태(소식·맛집·통계) 4:3 | 가로 1536×1024 | 좌우 합쳐 171px 잘라 1365×1024 | 640×480·320×240 | 빈 상태 상자 안 240px 폭, 가운데 | 60 KB |
| OG | 조립 | — | 1200×630 JPG 92 | 카카오톡 미리보기 | 200 KB |

파일 이름: `assets/img/<탭>-<자리>-<폭>.webp` (예: `places-banner-1440.webp`, `news-spot-480.webp`, `home-winter-desktop-1440.webp`). 챗GPT가 준 PNG 원본은 `assets/img/src/` 에 그대로 둡니다. 자르기와 줄이기는 파일을 받은 뒤 이쪽에서 합니다.

배너·스팟·빈 상태는 모두 `<img … onerror>` 방식으로 붙여 파일이 없으면 자리가 사라집니다. 홈 그림과 같은 규칙입니다.

## 4. 챗GPT 프롬프트

### 진행 방법

1. **대화 하나에서 전부 만듭니다.** 새 대화를 열고, 첫 메시지에 커버 그림(`assets/img/src/autumn-desktop.webp`, 또는 사이트 홈에서 저장한 그림)을 **첨부**한 뒤 아래 "기준 잡기" 메시지를 보냅니다. 이후 요청은 모두 같은 대화에서 이어 갑니다. 대화를 바꾸면 톤이 흔들립니다.
2. **한 번에 한 장씩** 요청합니다. 프롬프트마다 "위 기준대로"가 들어 있어 첫 메시지를 다시 붙일 필요가 없습니다.
3. 결과에 글자·깨진 손·이상한 얼굴이 있으면 새로 뽑지 말고 **부분 수정**을 시킵니다. 예: "왼쪽 두 번째 사람 손가락을 자연스럽게 고쳐 줘, 나머지는 그대로", "간판의 글자를 지우고 빈 나무판으로 바꿔 줘".
4. 마음에 들면 **원본 크기 PNG로 저장**합니다(미리보기 저장 아님). 이름은 프롬프트에 적힌 파일 이름으로.
5. 한 자리에 2~3장을 받아 두고 고르면 편합니다. 같은 프롬프트에 "다른 구도로 한 장 더"라고만 덧붙이면 됩니다.

## 6. 하지 않기로 한 것

- 실제 모임 사진, 멤버 얼굴 사진: 초상권과 방 분위기 문제. 일러스트만.
- 글자가 들어간 이미지(배너 위 문구, 포스터형): 글자는 HTML 로 얹는다. 이미지 안 글자는 깨지고 검색·접근성에서도 빠진다.
- 식당별 사진, 글별 사진: 첨부 기능이 없다. 생기면 `IMAGE_SPEC.md` 의 규격(목록 96×96, 상세 480×320)으로.
- 아이콘을 그림으로 바꾸기 — **40px 미만 자리는 유지**. 선 아이콘이 통일돼 있고 그 크기에서는 일러스트보다 또렷하다. 56px 이상으로 키울 수 있는 반복 자리(종류·단계·장 머리)는 7절 세트로 바꾼다(2026-09-21 개정).
- 섹션마다 장식 그림 — 제목 옆 한 번 쓰고 마는 장식은 여전히 두지 않는다. 다만 **같은 세트가 반복되는 자리**(맛집 종류, 참여 단계, 안내 장 머리, 글 종류)는 장식이 아니라 표지판이라 7절에서 넣기로 했다. 차트·표 옆, 입력 폼 안, 정산 결과 카드 안은 그대로 비워 둔다.
- 앱 아이콘을 그림으로: 지금의 보라 바탕 '동' 글자 아이콘이 32px 에서 가장 또렷하다. 생성 그림은 작은 크기에서 뭉개진다.

챗GPT 요청은 전부 **정사각 1024×1024** 한 가지입니다(404 한 장만 가로). 배경은 크림 단색으로 받아 그대로 쓰고, 자르기와 줄이기는 이쪽에서 합니다.

| 항목 | 값 |
|---|---|
| 챗GPT 요청 | 정사각 1024×1024, 크림 단색 배경, 사물은 가운데 70% 안 |
| 웹용 파일 | 320×320, 160×160 WebP |
| 표시 | 40~120px 둥근 네모(자리마다 다름, 아래 표) |
| 용량 상한 | 20 KB / 장 |
| 파일 이름 | `assets/img/<세트>-<이름>-<폭>.webp` (예: `cat-meat-320.webp`) |
| 대체 텍스트 | 없음(`alt=""`). 종류·단계 이름이 항상 글자로 옆에 있다 |
| 실패 처리 | 지금과 같은 `onerror` — 그림이 없으면 지금의 선 아이콘으로 돌아간다 |

### 7-2. 진행 방법

1. **지난번과 같은 대화에서 이어 갑니다.** 커버 그림과 4-0 기준이 이미 잡혀 있는 대화입니다. 대화를 잃었으면 새 대화에 커버 그림을 첨부하고 4-0 을 다시 보낸 뒤 시작합니다.
2. 먼저 아래 **7-3 세트 시작 메시지**를 한 번 보냅니다. 그 뒤로 한 장씩 요청합니다. 프롬프트마다 "세트 이름 n/m" 이 적혀 있어 챗GPT가 앞 장과 맞춥니다.
3. 한 세트는 **같은 날 한 번에** 뽑는 편이 결이 맞습니다. 세트 중간에 다른 세트를 섞지 않습니다.
4. 결과 확인은 4절 확인표에 두 가지를 더합니다. **배경이 무늬 없는 크림 단색인가**(그대로 쓰므로), **사물이 가운데 70% 안에 있는가**(둥근 네모로 잘라도 끝이 안 잘리게).
5. 저장은 원본 PNG, 이름은 프롬프트에 적힌 대로. 세트 단위로 zip 으로 주시면 됩니다.

### 8-1. 무엇이 문제인가

16장을 한 화면에 늘어놓고 보면 이유가 보입니다(`scratchpad/sheet-*.png` 로 확인).

| 진단 | 어디서 | 왜 문제인가 |
|---|---|---|

격자는 스티커 생성 횟수를 1/4로 줄이는 방법이고, 시험 3에서 격자가 제대로 나오는지(칸 크기 같은가, 사물이 칸을 넘지 않는가)도 같이 봅니다. 어긋나면 그 세트는 한 장씩 받습니다.

고르는 기준 셋: (1) 셋을 나란히 놓았을 때 한 작가 그림인가, (2) 시험 1의 왼쪽 아래에 흰 글자를 올려 읽히는가(이쪽에서 실제로 얹어 봅니다), (3) 시험 2·3을 60px 로 줄여도 알아보는가.

**결정(같은 날 저녁)**: 사용자가 두 대화를 나눠 비교할 여건이 안 되어 **시험 없이 A안으로 확정**했습니다. 실행은 지시서 파일 하나로 합니다 — `docs/gpt/brief.md`. 스타일 카드 + 진행 규칙 + 22항목(52장)이 한 파일에 있어, 챗GPT 대화에 파일을 올리면 1번을 바로 그리고, 그 뒤로는 아무 메시지나 보내면 다음 번호를 그립니다. 1번 결과가 이쪽 확인의 시험 역할을 합니다(글자 얹어 보기, 팔레트). A안이 안 맞으면 B 스타일 카드로 첫 부분만 바꿔 다시 올립니다.

### 8-5. 스팟 넷은 장면을 바꾼다

사물 나열이던 스팟을 '뜻이 한눈에 보이는 한 덩어리'로 바꿉니다. 4-4~4-7 의 장면 설명은 아래로 대체합니다.

| 스팟 | 새 장면 |
|---|---|
| 활동 통계 `report-spot` | 밤하늘 아래 말풍선 여섯 개가 키를 달리해 막대 그래프처럼 나란히 서 있고, 가장 큰 말풍선 안에 작은 달. 말풍선은 크림, 하늘은 자두 |
| 모임 정산 `settle-spot` | 시험 2 그대로(다섯 조각 접시와 동전) |
| 소식 `news-spot` | 말풍선 셋이 층층이 떠오르고 맨 위 말풍선에 작은 종이비행기가 앉아 있음. 아래에 작은 종 하나 |
| 오늘 뭐 먹지 `places-pick` | 지금 룰렛 그대로, 새 화풍으로. 칸은 여섯, 음식은 실루엣이 또렷한 것만(국수, 고기, 초밥, 피자, 만두, 밥) |
| 오프라인 `offline-spot` | 지금 종이컵 전화기 그대로, 새 화풍으로 |

빈 상태 셋은 4-8~4-10 장면을 유지하되 전부 **저녁**으로 통일하고(소식 빈 상태의 낮 창문을 저녁 창문으로), 8-3 의 빈 상태 구도 문장을 붙입니다.

### 8-6. 다시 만드는 순서 — 지시서 22항목, 52장

스티커는 한 장에 4칸(정사각 2×2) 또는 6칸(가로 3×2) 격자로 받아 이쪽에서 잘라 씁니다. 칸 하나가 512px 라 웹용 320·160 에 충분합니다. 장면 그림은 한 장씩입니다. 번호는 `docs/gpt/brief.md` 와 같습니다.

| 항목 | 무엇 | 장수 | 비고 |
|---|---|---|---|
| 1~4 | 가을 가로·세로, 안내·맛집 배너 | 4 | 여기까지 오면 지금 보이는 커버가 전부 새 화풍 |
| 5 | 탭 스팟 격자 3×2 — 통계·소식·정산·오늘 뭐 먹지·오프라인·정기 참여 | 6 | |
| 6~8 | 음식 격자 1·2, 참여 단계 격자 | 12 | 여기까지 오면 본문이 바뀜 |
| 9~11 | 빈 상태 소식·맛집·통계 | 3 | 전부 저녁 |
| 12~13 | 안내 규칙 격자(6), 글 종류 격자(4) | 10 | |
| 14~19 | 겨울·봄·여름 가로·세로 | 6 | 인물 셋, 구도 문장 포함 |
| 20~22 | 정산 단계 격자, 칭호 격자, 404 | 11 | |

그림이 도착하는 묶음마다 이쪽에서 격자 자르기·웹 파일·연결·대비 측정·3폭 캡처를 하고, OG 5장은 배너·스팟이 바뀔 때 다시 조립합니다. 지시서 항목 번호와 파일 이름이 곧 이쪽 작업 단위입니다.

### 8-7. 요청할 때 지킬 것

- **대화 하나에서 끝까지.** 스타일 카드가 첫 메시지에 있어야 뒤의 그림이 흔들리지 않는다. 대화가 길어져 결이 흔들리면, 가장 마음에 든 그림 한 장을 첨부하며 "이 그림과 같은 화풍으로"를 한 줄 덧붙인다.
- 4절·7절 프롬프트의 "위 기준대로"는 이제 스타일 카드를 가리킨다. 계절 프롬프트의 "다섯 친구·인물 설정" 문단은 **빼고** 보낸다(인물 셋, 얼굴 없음).
- 장면 프롬프트에는 8-3 구도 문장을 붙인다. 스티커에는 붙이지 않는다.
- 결과 확인은 4절 확인표 + "팔레트 밖 색이 없는가" + "비워 달라고 한 면이 비어 있는가".
