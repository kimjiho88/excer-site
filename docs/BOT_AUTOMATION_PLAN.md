# 봇 자동화 기획 (2026-10-22, 기획안)

상태: 1절 신입 자동 태그 인사는 만듦(2026-10-24, 105차와 106차, 107차에 멤버 읽기 고침, 108차에 greet now, 109차에 신입 독려와 여러 줄 인사 글, 110차에 독려만(16:30 읽고 17:00 보냄), 118차에 멤버 읽기 하루 세 번과 운영 화면의 지금 읽기, 120차에 신입 독려를 매일로, 기본은 꺼짐). 7절 대화 내보내기와 채팅 언어 리포트는 만듦(2026-10-31, 123차, 봇 판 2026-10-31.1, 기본은 꺼짐. 실제 화면 확인은 export study 로). 나머지는 기획만. 만들 때는 절마다 '정할 것'을 운영자가 먼저 정하고, 태블릿에서 화면을 살핀 뒤 시험 방에서 '보기만'으로 시작한다.

목적: 봇(tools/excer_bot.py)으로 신입 안내, 벙 참석, 운영 점검, 방 분위기 관리를 돕는다. 판단과 조치는 운영진이 한다.

## 0. 지금 봇이 하는 일과 원칙

- 벙 알림(새 벙, 바뀜, 마감, 정원 참, 다시 모집, 취소)을 올리고, 오늘 벙 공지 카드를 올려 공지로 건다.
- 하루 세 번(서버가 지난 4주 시간대별 방문에서 붐비기 시작하는 때의 1시간 전으로 정한 시각, 2026-10-25 부터)과 운영 화면의 '지금 멤버 읽기' 때 방 메뉴의 대화상대 칸에서 멤버 닉네임을 읽어 사이트 닉네임 목록에 올린다.
- 보이스룸을 지킨다(docs/BOT_VOICE_ROOM.md). 매일 09:00 시험 방에 '봇 정상' 한 줄.
- 운영 화면의 봇 원격 조종(공지 멈춤, 전체 멈춤, 다시 켜기)을 1분 안에 따른다.
- 켜 두면(export on, 기본은 꺼짐) 매일 05:40 방의 대화 내용을 텍스트로 내보내 태블릿 안에서 사이트와 같은 분석기로 읽고 결과(사람별 집계, 채팅 언어 점검)만 서버에 올린다(7절). 운영 화면의 '지금 내보내기' 도 따른다.
- 원칙: 카카오톡은 올릴 것이 있을 때, 멤버를 읽을 때, 대화를 내보낼 때(켰으면)만 건드린다. 대화 내용은 사람이 보지 않는 분석기로만 읽고 방이나 다른 곳에 옮기지 않으며 원문을 서버에 올리지 않는다. 기록 파일에 멤버 이름과 대화 글을 적지 않는다.
- 이 기획이 원칙을 바꾸는 곳: 1절은 멤버 읽기를 더 자주 한다. 7절은 대화 파일을 하루 한 번 읽는다(만듦).

## 1. 신입 자동 태그 인사

- 신입: 닉네임 끝 네 자리가 입장일(월일)인 사람. 끝의 하트는 양식 밖이라 무시한다.
- 찾기: 10분마다 방 인원 수만 본다(방 화면 머리나 방 메뉴의 대화상대 수, 태블릿에서 살펴 정한다). 늘었으면 명단 전체를 읽어 앞 명단과 견준다. 새 이름 가운데 입장일이 오늘이나 어제인 사람만 인사한다.
- 이름만 바꾼 기존 멤버(사라진 이름과 닉네임 첫 칸, 출생연도가 같음)는 인사하지 않는다. 한 사람에게 한 번. 인사한 사람은 이름 대신 지문으로 태블릿에 적는다.
- 보내기: 찾은 뒤 바로(들어오고 10~20분 안). 그 사이 들어온 사람을 한 메시지에 모아 태그한다.
- 조용한 시간(quiet)에는 인원 수를 보지 않는다. 끝난 뒤 명단을 한 번 읽어 밤에 들어온 사람을 아침 9시에 모아 인사한다.
- 태그: 입력 칸에 @ 를 치고 닉네임을 붙여넣어 뜨는 목록에서 닉네임이 글자 그대로 같은 줄만 누른다. 못 찾으면 태그 없이 이름만 적어 보낸다. 보내기 전에 입력 칸 글을 확인한다(지금 보내기와 같다).
- 문구(예, 승인 전): "@신입 안녕하세요 벙은 매일 열리니 빠른 벙참 부탁드립니다~^^". 운영진이 정한 한 가지만 쓴다(돌려 쓰는 문구는 ENGAGEMENT_PLAN 10절의 하지 않을 것).
- 선택: 닉네임이 양식(닉네임 지역 성별 출생연도 입장일)에 맞지 않으면 인사 아래에 양식 한 줄.
- 켜는 순서: 보기만(누구에게 인사할지 시험 방에만 올림), 시험 방에서 @ 목록 화면 살피기(보내지 않음), 알릴 방에 켜기. 켜고 끄기는 운영 화면 봇 원격 조종에 둔다.
- 겹침: 카카오 방장봇 입장 메시지를 쓰면 인사가 두 번 나간다. 하나만 쓴다.
- 통계: 운영 분석의 '입장 뒤 60분 안 환영 비율'에서 봇 인사는 빼고 센다.

### 1-1. 만든 것 (2026-10-24, 105차)

- 명령: `python excer_bot.py greet on`(알릴 방에 태그해서), `greet test`(시험 방에 태그 없이, 무엇을 보낼지 보기), `greet off`, `greet text "인사 글"`(글을 안 적으면 클립보드, 봇 열쇠가 든 글은 받지 않음), `greet study`(시험 방 태그 목록 화면 살피기, 보내지 않음, 이름 가림), `greet now "닉네임"`(알릴 방에 그 사람을 태그해 인사 글을 한 번 보냄. 태그 목록에 그 이름이 없으면 보내지 않음. 알릴 방에서 태그가 되는지 볼 때, run 을 멈춘 뒤), `greet remind 1 17:00`(신입 독려: 며칠마다 몇 시. 기본은 매일 17:00. `greet remind off`), `greet watch on`(입장 즉시 인사 켬. `greet watch off` 가 기본, 독려만), `greet`(설정 보기). 켜고 끈 뒤 run 을 다시 켠다. 기본은 꺼짐.
- 인사 글 기본값(운영자가 정함, 2026-10-25): "님 반갑습니다 🙌 공지 및 웹사이트 '오늘의 벙' 보시고 벙에 참여해 주세요." 다음 줄 "2주 안에 첫 벙참 부탁드리겠습니다. 🙏". 보내는 글은 태그(사람마다) 뒤에 이 글 하나. 줄바꿈은 그대로 나간다(다섯 줄까지).
- 신입 독려(109차, 110차, 120차): greet watch off(기본)면 입장 즉시 인사는 하지 않고 독려만 한다. 매일 16:30(17:00 의 30분 전)에 멤버를 한 번 읽어 끝에 입장일이 붙은 사람 모두(오늘부터 30일 전까지, 오늘 인사한 사람은 빼고)를 모아 두고 17:00 에 같은 인사 글을 태그해 보낸다. 그 사이에는 방을 열지 않는다. 읽기가 안 되면 5분, 10분, ... 뒤 다시, 읽기가 늦어지면 읽은 뒤 바로, 17:00 에서 세 시간이 지나도록 못 읽었으면 다음 날. 조용한 시간 안의 시각은 안 된다(명령이 알린다). 여덟 명 넘으면 1분 뒤 다음 메시지로. `greet remind 1 17:00`(며칠마다 몇 시. 2026-10-27 부터 기본이 매일, 그 전은 이틀마다), `greet remind off`. 주기나 시각을 바꾸면(명령이나 새 판) 다음 확인 때부터 새 주기로 한다(옛 주기로 잡아 둔 다음 할 일 시각은 버림. 2026-10-28, 판 2026-10-28.1. 그 전 판은 잡아 둔 시각이 지나야 새 주기가 먹었다). `greet watch on` 이면 예전처럼 10분마다 인원 수를 보고 늘면 바로 읽어 처음 보는 신입에게 인사하고, 독려는 17:00 뒤 첫 확인 때 읽어 바로 보낸다(그때 처음 본 신입은 앞에).
- 찾기(greet watch on 일 때. 기본은 watch off 라 독려만 한다, 110차): 10분마다 알릴 방 머리의 인원 수('91명')를 본다. 늘었으면, 또는 3시간마다(한 명 나가고 한 명 들어와 수가 같을 때) 멤버를 읽는다. 처음 보는 이름 가운데 끝의 입장일이 오늘부터 이틀 전까지인 사람만 신입. 켜면(끄고 다시 켜도, on 과 test 를 바꿔도) 지금 멤버를 기준으로만 잡는다. 전에 본 이름, 전에 인사한 이름은 빼고, 이름만 고친 사람도 뺀다: 같은 입장일을 단 이름이 이번에 사라졌으면(인사한 뒤 첫 칸, 지역, 출생연도를 고침) 빼고, 첫 칸과 출생연도가 같은 이름이 사라졌으면 그 이름이 날짜 없이 며칠 안에 처음 보인 신입일 때만 인사한다(날짜 없이 들어와 날짜를 단 신입). 여섯 명 이상 새로 보이는데 인원 수가 그만큼 늘지 않았으면 인사하지 않는다(밤사이 실제로 들어온 여럿은 인사). 읽기나 방 열기에 실패하면 5분, 10분, 20분, 40분, 60분 뒤 다시.
- 조용한 시간에는 쉬고, 끝난 뒤 첫 확인(예: 07:30)에 밤에 들어온 신입에게 인사한다(기획의 아침 9시 대신). 운영 화면의 전체 멈춤 중에도 쉰다. 운영 화면에서 켜고 끄는 단추는 아직 없다(명령으로).
- 보내기: 먼저 입력 칸을 비우고(앞뒤 글자 지우기, 여러 줄 남은 글도) 빈 것을 확인한다. 사람마다 입력 칸에 '@' 를 치고 닉네임 첫 칸을 붙여넣어, 새로 뜬 것 가운데 입력 칸 위, 방 칸 쪽에 있고 닉네임이 글자 그대로 같은 줄을 누른다. 원래 있던 목록 칸(대화 목록, 아래 끝은 줄어도 같은 것으로 봄, 감싼 목록 어느 것이든) 안의 보낸 사람 이름은 누르지 않는다. 들어간 글이 '@닉네임' 그대로일 때만 태그한 것으로 보고, 아니면 친 글자만 지우고 '@닉네임' 글로 적는다. 끝에 인사 글을 붙이고 입력 칸 글이 만든 글과 똑같을 때만 보낸다. 다르면 비우고 글로만 다시 보낸다. 한 메시지에 여덟 명까지(넘치면 1분 뒤 다음 메시지).
- 입력 칸 비우기: 앞뒤 글자 지우기로 안 지워지면(한 글자씩 안 지워지는 태그) 모두 골라(Ctrl+A) 지운다. 그래도 남으면 보내지 않고 신입 인사를 멈추며, status 와 아침 '봇 정상' 줄에 '신입 인사: 멈춤' 을 보인다(공지 보내기까지 막히지 않게 알림). 입력 칸을 손으로 비운 뒤 greet on 하고 run 을 다시 켠다.
- 두 번 올리지 않기: 전송을 누르기 바로 전에 그 사람들을 인사한 것으로 적는다. 그 뒤로 화면 읽기 같은 것이 실패해도 다시 보내지 않는다(기록에 '전송은 눌렀고 그 뒤 확인 실패').
- 실패: 같은 사람에게 세 번 못 보내면 그만. 실패 수는 보기나 읽기에 성공하면 0으로. 실패 뒤에는 5분에서 60분 쉬고, greet on 이 쉬는 것을 푼다(run 을 다시 켜면 바로). 기록은 처음과 열두 번째마다만. 보낼 사람은 입장일이 이틀을 넘었거나 여섯 시간 넘게 못 보냈으면 버린다. 기록과 상태 파일에는 이름 대신 지문(보낼 사람 이름은 보낼 때까지만 상태 파일에), 안 될 때의 진단 파일에도 인사 글을 적지 않는다. 180일 넘게 안 보인 이름과 1년 지난 인사 기록은 지운다.
- 통계: 운영 분석(assets/ops-analyzer.js)의 봇 판정을 통계 화면과 같게(끝이 '-bot' 도 봇) 해서 봇 인사가 환영 비율에 들지 않는다.
- 확인할 것: 오픈채팅 태그 목록의 실제 모양. 태그가 안 되면 '@닉네임' 글로 나가므로, 그때 `greet study` 결과로 맞춘다.

## 2. 신입 첫 벙 챙기기 (입장 2주 안 첫 모임)

- 근거: 사이트 모임 글의 참석 명단. 참석 이름은 멤버 목록에서 고른 것이라 닉네임과 맞는다. 맞출 때 입장일 네 자리와 하트는 무시한다(운영 화면 '닉네임으로 멤버 찾기'와 같은 규칙).
- 7일째 아침: 닉네임에 입장일이 남아 있고 참석 기록이 없는 신입을 한 메시지에 모아 태그하고 이번 주 벙 링크를 붙인다. 방에 올릴지는 정할 것.
- 14일 넘김: 방에 올리지 않고 운영진 방에만 알린다.
- 선택, 날떼 안내: 첫 벙 다음 날 닉네임에서 입장일을 떼 달라고 태그한다(운영 방식에 맞을 때).
- 참석 명단은 실제 참석과 다를 수 있다(신청만 하고 오지 않음). 기한 넘김은 운영진이 확인한 뒤 조치한다.

## 3. 벙 참석자 태그

- 변경, 취소 알림에 참석자 태그: 지금 올리는 시간, 장소, 신청 마감 바뀜과 취소 알림에 그 벙 참석자를 태그한다. 메시지 수는 그대로다.
- 시작 전 태그: 시작 1시간 전(시각은 정함) 참석자를 태그하고 시간과 장소를 적는다. 벙 수만큼 메시지가 늘어서 켜고 끄기와 시각은 운영 화면에서 정한다.
- 1절의 태그 기능을 그대로 쓴다.

## 4. 운영진 보고 (운영진 방에만)

- 보낼 곳: 봇이 들어가 있는 운영진 방. 지금은 시험 방.
- 아침 보고: 09:00 '봇 정상' 줄에 더한다. 어제 들어옴, 나감, 이름 바꿈, 양식 틀림, 첫 벙 기한 다가옴과 넘김, 오늘 벙 수, 운영 화면 링크.
- 재입장 감시: 명단 이력을 서버에 쌓아 다시 들어온 사람, 재입장 한도(81 이하 1회, 82 이상 3회) 넘김, 내보낸 사람이 다시 들어옴을 찾자마자 알린다. SQL 한 번(명단 이력 표, 봇 열쇠로만 쓰기).
- 2개월 미참여: 주 1회 수만 보낸다(이름은 운영 화면). 방에는 올리지 않는다(사람을 지목한다).
- 이름은 운영진 방 글에만 쓰고 봇 기록 파일에는 적지 않는다.

## 5. 활성화 (선택)

- 자리 남은 오늘 벙 막판 알림: 시작 3시간 전 모집 중이고 자리가 남은 벙만 한 줄. 공지 카드에 이미 있고 ENGAGEMENT_PLAN 5-5의 '정기 자동 알림은 쓰지 않는다'와 겹쳐 뒤로 미룬다.
- 통계 발행 알림: 월간 통계를 발행하면 방에 링크 한 줄(지금은 운영진이 손으로 올린다).
- 키워드 자동응답(정산, 맛집, 규칙, 통계, 모임): 봇은 대화를 읽지 않으므로 카카오 방장봇 키워드로 한다(코드 없음, 방장이 앱에서 설정. ENGAGEMENT_PLAN 5-5).

## 6. 봇 관리

- 원격 새 판: 운영 화면 '새 판 받고 다시 켜기'. 봇이 1분 안에 읽고 저장소의 새 판을 받아 문법 검사 뒤 스스로 다시 켠다. 켜지 못하면 옛 판(.bak)으로 돌아간다. 1차 판에 넣으면 그 뒤 판은 태블릿을 만지지 않고 올린다.
- 운영 화면 '공지 다시 걸기' 단추.
- 운영 화면 봇 상태 자세히: 마지막으로 올린 글, 최근 실패, 보이스룸, 멤버 읽기 결과(지금은 마지막 확인 시각과 판만).
- 재부팅 뒤 자동 켜기: Termux:Boot. 무선 디버깅은 재부팅 뒤 손으로 켜야 할 수 있다.

## 7. 대화 내보내기와 채팅 언어 리포트 (2026-10-31, 123차, 봇 판 2026-10-31.1)

목적: 운영 대시보드의 채팅 언어 리포트(OPS_DASHBOARD_PLAN 9절)와 대화 기록 분석이 운영자가 파일을 올리지 않아도 매일 갱신되게 한다. 방에는 아무것도 올리지 않는다. 리포트는 운영자만 본다(2026-10-30 운영자 지시. 옛 7절의 '방에 수를 올리기'는 하지 않는다).

### 7-1. 흐름

1. 매일 export.at(기본 05:40, 그 뒤 세 시간 안)에 봇이 서버에서 운영 화면의 설정(`bot_ops_cfg`: 단어 목록 설정과 직접 이은 줄)과 저장소 main 의 분석기 파일 넷(assets/chat-parser.js, assets/ops-lang.js, assets/ops-analyzer.js, tools/ops_scan.js)을 받아 둔다(바뀐 것만 바꿔 쓴다).
2. 알릴 방을 열고 세 줄 단추(방 메뉴), 설정 단추(방 메뉴 위 띠의 '채팅방 설정'), 채팅방 설정의 '대화 내용 내보내기'(맨 아래 '채팅방 데이터' 칸. 여섯 번까지 밀며 찾고, '대화 내용 관리' 안이면 들어가서), 내보내기 화면의 '텍스트 메시지만 저장'(텍스트가 든 줄. 다른 줄 '모든 메시지 내부저장소에 저장'은 누르지 않는다. 글이 보이스룸 작은 창에 가려 있으면 그 줄의 가리지 않은 자리), 공유 창이 뜨면 받을 앱(설정 share 순서. 기본 Termux, 파일, Files, 내 파일, 드라이브, Drive)을 누르고, Termux 의 받기 창('Save file in ~/downloads/': OPEN DIRECTORY, 취소, EDIT)에서는 EDIT 를 누른다(봇이 ~/bin/termux-file-editor 에 바로 끝나는 스크립트를 두어 파일만 남고 세션이 남지 않는다. 다른 스크립트가 이미 있으면 건드리지 않고 OPEN DIRECTORY 를 누르며, 그러면 ~/downloads 세션이 하나씩 남는다). 다른 앱의 창은 확인 단추(저장, 확인). 해제, 나가기, 삭제, 신고, 차단, 초기화, 강퇴, 탈퇴가 든 것은 어떤 흐름에서도 누르지 않는다(멤버 '내보내기 해제', '대화 내용 모두 삭제'). 2026-10-31 살피기 둘로 파일을 받는 데까지 확인했다(29.8MB).
3. 파일이 오기를 기다린다(wait_min, 기본 15분): 공유 창으로 받았으면 Termux 다운로드 폴더(~/downloads)에 새로 생긴 .txt(크기가 그대로일 때까지), 공유 창 없이 기기 저장소에 바로 저장하는 판이면 Download, Documents, 카카오톡 폴더(네 단계까지)의 새 .txt 를 adb pull 로 받고 기기의 것은 지운다(여섯 초마다 본다). 끝나면(안 되어도) 카카오톡을 앞으로 하고 뒤로 키로 방까지 닫는다.
4. node 로 tools/ops_scan.js 를 돌린다: 파일을 4MB 조각씩 읽어(170MB 도 메모리에 다 올리지 않음) 사이트와 같은 분석기로 사람별 집계(ledger)와 채팅 언어 점검(lang)을 만든다. 대화 파일은 지운다(export.keep 이 아니면).
5. 결과를 `bot_analysis_put`(봇 열쇠)으로 올린다: ledger, lang, status(마친 때와 한 줄). 종류마다 서버에 한 줄(통째로 바꿈, 8MB 까지). 대화 원문은 올리지 않는다(분석기 결과만: 사람별 집계, 신호 발췌와 걸린 줄 발췌 80자). 올린 뒤 결과 파일도 지운다.
6. 운영 화면은 열 때 봇 분석이 저장본보다 새것이면 띠를 보이고, '반영하고 저장' 을 누르면 파일을 올린 것과 같은 길(사람 잇기, 서버에 저장)로 저장한다. 데이터 탭의 '열 때 새 결과를 바로 반영하고 저장' 을 켜면 묻지 않고 저장한다. '지금 내보내기' 는 `bot_control_set(비밀번호, 'export', 0)` 이고 봇이 1분 안에 시작한다(30분 안의 요청만, 한 번만. 전체 멈춤 중이면 그렇다고 알린다).

### 7-2. 실패와 다시

- 실패하면 20분, 40분, 60분 뒤 다시(하루 세 번까지). 분석까지 하고 올리기만 실패했으면 다음에는 올리기만 다시 한다(세 시간 안).
- 전체 멈춤 중에는 쉬고, 보내기나 읽기가 막 실패해 쉬는 중이면 다음에. 조용한 시간에도 한다(방에 올리는 것이 없다). 정한 시각 전 한 시간 안에 지금 내보내기로 이미 했으면 그날은 건너뛴다.
- 결과와 실패는 status 줄로 운영 화면 데이터 탭에, 태블릿의 `python excer_bot.py status` 와 아침 '봇 정상' 줄에 보인다.
- 카카오톡 화면이 바뀌어 단추를 못 찾으면 실패로 적고 멈춘다(위험한 것은 누르지 않는다). `python excer_bot.py export study` 로 화면을 적어 보내면 단추 이름을 맞춘다. 지나온 화면은 excer_bot_ui.txt 에(대화 글과 이름은 글자 수만).

### 7-3. 개인정보와 원칙

- 대화 파일은 태블릿 안에서만 읽고 분석 뒤 지운다. 서버에는 분석 결과만(운영 화면이 파일을 올릴 때 저장하는 것과 같다). 보는 사람은 운영자뿐이다.
- 살피기(export study)와 진단 파일은 대화 글과 이름을 글자 수로 가린다. 기록(log)에는 수와 까닭만 적는다.
- 방에는 아무것도 올리지 않는다. 개인별 수를 방에 공개하지 않는다(8절).
- 0절의 '대화 내용은 읽지 않는다' 는 이 기능만큼 좁힌다: 봇은 대화를 사람이 보지 않는 분석기로만 읽고 결과만 올린다. 대화 글을 방이나 다른 곳에 옮기지 않는다.

### 7-4. 명령과 설정

- `export`: 설정과 마지막 결과. `export on`, `export off`, `export at 05:40`(run 을 다시 켜야 적용). `export check`: node, 분석기 파일, 봇 열쇠, Termux 다운로드 폴더. `export study`: 화면을 적고 실제로 한 번 내보내 파일 크기만 적은 뒤 지움. `export now`: 지금 한 번(run 을 멈추고).
- 설정 export: on, at, share(받을 앱 순서), node(명령), wait_min(공유 창과 파일을 기다리는 분, 15), keep(대화 파일 남김, 기본 끔). Termux 에 nodejs(pkg install nodejs)가 있어야 한다.
- 처음 켤 때: SQL(sql/2026-10-31-bot-analysis.sql) 한 번, `python excer_bot.py update`, `pkg install nodejs`, `export check`, `export study`(결과를 보내 단추 이름을 맞춘다), `export on`, run 다시 켜기.

### 7-5. 안 한 것과 남은 것

- 방에 비속어 수 올리기(옛 7절): 운영자 지시로 운영자만 보는 리포트로 바꿨다(122차). 방 공지는 운영자가 올린다.
- 파이썬으로 파서를 옮기기: node 로 사이트와 같은 파일을 그대로 돌린다(두 벌이 어긋나지 않게).
- 실제 태블릿 화면은 2026-10-31 살피기 둘로 끝까지 확인했다: 방 메뉴의 설정 단추, 채팅방 설정의 '대화 내용 내보내기', 내보내기 화면('텍스트 메시지만 저장', '모든 메시지 내부저장소에 저장'), 공유 창(intentresolver, Termux 줄), Termux 의 받기 창, 파일 29.8MB. 봇 판 2026-10-31.2 에 작은 창에 가린 글은 줄을 누르는 것과 공유 창 없이 바로 저장하는 판을, 2026-10-31.3 에 받기 창의 EDIT(세션이 남지 않게)를 반영했다.

## 8. 자동화하지 않을 것

- 경고, 강제퇴장: 판단은 운영진, 봇은 알리기만.
- 대화 글을 서버나 저장소에 남기기.
- 개인별 비속어 수를 방에 공개하기.
- 정산 링크를 방에 올리기, 2개월 참여 기준 충족 여부 공개, 칭호 수상자 이름 올리기, 시간대 인사(ENGAGEMENT_PLAN 10절).

## 10. 정할 것

1. 신입 인사 문구(기본은 운영자 예시 그대로), 양식 줄과 링크를 붙일지.
2. 방장봇 입장 메시지를 쓰는지(쓰면 1절과 겹친다).
3. 첫 벙 안내를 방에서 태그할지, 운영진 방에만 알릴지.
4. 시작 전 참석자 태그를 켤지와 시각.
5. 비속어: 정함(122차, 123차). 운영자만 보는 리포트로 하고 방에는 올리지 않는다. 가벼운 비속어와 추임새도 같은 목록으로 센다(운영자가 끌 수 있다).
6. 비속어: 방 공지 문구는 운영자가 정했다(2026-10-30 공지).
7. 운영진 방: 시험 방을 그대로 쓸지, 운영진 방을 따로 만들지.

## 11. 확인한 사실과 확인할 것
