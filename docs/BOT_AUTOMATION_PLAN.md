# 봇 자동화 기획 (2026-10-22, 기획안)

상태: 1절 신입 자동 태그 인사는 만듦(2026-10-24, 105차와 106차, 봇 판 2026-10-24.4, 기본은 꺼짐). 나머지는 기획만. 만들 때는 절마다 '정할 것'을 운영자가 먼저 정하고, 태블릿에서 화면을 살핀 뒤 시험 방에서 '보기만'으로 시작한다.

목적: 봇(tools/excer_bot.py)으로 신입 안내, 벙 참석, 운영 점검, 방 분위기 관리를 돕는다. 판단과 조치는 운영진이 한다.

## 0. 지금 봇이 하는 일과 원칙

- 벙 알림(새 벙, 바뀜, 마감, 정원 참, 다시 모집, 취소)을 올리고, 오늘 벙 공지 카드를 올려 공지로 건다.
- 매일 05:10 방 메뉴의 대화상대 칸에서 멤버 닉네임을 읽어 사이트 닉네임 목록에 올린다.
- 보이스룸을 지킨다(docs/BOT_VOICE_ROOM.md). 매일 09:00 시험 방에 '봇 정상' 한 줄.
- 운영 화면의 봇 원격 조종(공지 멈춤, 전체 멈춤, 다시 켜기)을 1분 안에 따른다.
- 원칙: 카카오톡은 올릴 것이 있을 때와 멤버를 읽을 때만 건드린다. 대화 내용은 읽지 않는다. 기록 파일에 멤버 이름을 적지 않는다.
- 이 기획이 원칙을 바꾸는 곳: 1절은 멤버 읽기를 더 자주 한다. 7절은 대화 파일을 하루 한 번 읽는다.

## 1. 신입 자동 태그 인사

- 신입: 닉네임 끝 네 자리가 입장일(월일)인 사람. 끝의 하트는 양식 밖이라 무시한다.
- 찾기: 10분마다 방 인원 수만 본다(방 화면 머리나 방 메뉴의 대화상대 수, 태블릿에서 살펴 정한다). 늘었으면 명단 전체를 읽어 앞 명단과 견준다. 새 이름 가운데 입장일이 오늘이나 어제인 사람만 인사한다.
- 이름만 바꾼 기존 멤버(사라진 이름과 닉네임 첫 칸, 출생연도가 같음)는 인사하지 않는다. 한 사람에게 한 번. 인사한 사람은 이름 대신 지문으로 태블릿에 적는다.
- 보내기: 찾은 뒤 바로(들어오고 10~20분 안). 그 사이 들어온 사람을 한 메시지에 모아 태그한다.
- 조용한 시간(quiet)에는 인원 수를 보지 않는다. 끝난 뒤 명단을 한 번 읽어 밤에 들어온 사람을 아침 9시에 모아 인사한다.
- 태그: 입력 칸에 @ 를 치고 닉네임을 붙여넣어 뜨는 목록에서 닉네임이 글자 그대로 같은 줄만 누른다. 못 찾으면 태그 없이 이름만 적어 보낸다. 보내기 전에 입력 칸 글을 확인한다(지금 보내기와 같다).
- 문구(예, 승인 전): "@신입 안녕하세요 벙은 매일 열리니 빠른 벙참 부탁드립니다~^^". 운영진이 정한 한 가지만 쓴다(돌려 쓰는 문구는 ENGAGEMENT_PLAN 10절의 하지 않을 것).
- 선택: 닉네임이 양식(닉네임 지역 성별 출생연도 입장일)에 맞지 않으면 인사 아래에 양식 한 줄.
- 켜는 순서: 보기만(누구에게 인사할지 시험 방에만 올림), 시험 방에서 @ 목록 화면 살피기(보내지 않음), 알릴 방에 켜기. 켜고 끄기는 운영 화면 봇 원격 조종에 둔다.
- 겹침: 카카오 방장봇 입장 메시지를 쓰면 인사가 두 번 나간다. 하나만 쓴다.
- 통계: 운영 분석의 '입장 뒤 60분 안 환영 비율'에서 봇 인사는 빼고 센다.

### 1-1. 만든 것 (2026-10-24, 105차)

- 명령: `python excer_bot.py greet on`(알릴 방에 태그해서), `greet test`(시험 방에 태그 없이, 무엇을 보낼지 보기), `greet off`, `greet text "인사 글"`(글을 안 적으면 클립보드, 봇 열쇠가 든 글은 받지 않음), `greet study`(시험 방 태그 목록 화면 살피기, 보내지 않음, 이름 가림), `greet`(설정 보기). 켜고 끈 뒤 run 을 다시 켠다. 기본은 꺼짐.
- 인사 글 기본값: 운영자 예시 "안녕하세요 벙은 매일 열리니 빠른 벙참 부탁드립니다~^^". 보내는 글은 태그(사람마다) 뒤에 이 글 하나.
- 찾기: 10분마다 알릴 방 머리의 인원 수('91명')를 본다. 늘었으면, 또는 3시간마다(한 명 나가고 한 명 들어와 수가 같을 때) 멤버를 읽는다. 처음 보는 이름 가운데 끝의 입장일이 오늘부터 이틀 전까지인 사람만 신입. 켜면(끄고 다시 켜도, on 과 test 를 바꿔도) 지금 멤버를 기준으로만 잡는다. 전에 본 이름, 전에 인사한 이름은 빼고, 이름만 고친 사람도 뺀다: 같은 입장일을 단 이름이 이번에 사라졌으면(인사한 뒤 첫 칸, 지역, 출생연도를 고침) 빼고, 첫 칸과 출생연도가 같은 이름이 사라졌으면 그 이름이 날짜 없이 며칠 안에 처음 보인 신입일 때만 인사한다(날짜 없이 들어와 날짜를 단 신입). 여섯 명 이상 새로 보이는데 인원 수가 그만큼 늘지 않았으면 인사하지 않는다(밤사이 실제로 들어온 여럿은 인사). 읽기나 방 열기에 실패하면 5분, 10분, 20분, 40분, 60분 뒤 다시.
- 조용한 시간에는 쉬고, 끝난 뒤 첫 확인(예: 07:30)에 밤에 들어온 신입에게 인사한다(기획의 아침 9시 대신). 운영 화면의 전체 멈춤 중에도 쉰다. 운영 화면에서 켜고 끄는 단추는 아직 없다(명령으로).
- 보내기: 먼저 입력 칸을 비우고(앞뒤 글자 지우기, 여러 줄 남은 글도) 빈 것을 확인한다. 사람마다 입력 칸에 '@' 를 치고 닉네임 첫 칸을 붙여넣어, 새로 뜬 것 가운데 입력 칸 위, 방 칸 쪽에 있고 닉네임이 글자 그대로 같은 줄을 누른다. 원래 있던 목록 칸(대화 목록, 아래 끝은 줄어도 같은 것으로 봄, 감싼 목록 어느 것이든) 안의 보낸 사람 이름은 누르지 않는다. 들어간 글이 '@닉네임' 그대로일 때만 태그한 것으로 보고, 아니면 친 글자만 지우고 '@닉네임' 글로 적는다. 끝에 인사 글을 붙이고 입력 칸 글이 만든 글과 똑같을 때만 보낸다. 다르면 비우고 글로만 다시 보낸다. 한 메시지에 여덟 명까지(넘치면 1분 뒤 다음 메시지).
- 입력 칸 비우기: 앞뒤 글자 지우기로 안 지워지면(한 글자씩 안 지워지는 태그) 모두 골라(Ctrl+A) 지운다. 그래도 남으면 보내지 않고 신입 인사를 멈추며, status 와 아침 '봇 정상' 줄에 '신입 인사: 멈춤' 을 보인다(공지 보내기까지 막히지 않게 알림). 입력 칸을 손으로 비운 뒤 greet on 하고 run 을 다시 켠다.
- 두 번 올리지 않기: 전송을 누르기 바로 전에 그 사람들을 인사한 것으로 적는다. 그 뒤로 화면 읽기 같은 것이 실패해도 다시 보내지 않는다(기록에 '전송은 눌렀고 그 뒤 확인 실패').
- 실패: 같은 사람에게 세 번 못 보내면 그만. 실패 수는 보기나 읽기에 성공하면 0으로. 기록은 처음과 열두 번째마다만. 보낼 사람은 입장일이 이틀을 넘었거나 여섯 시간 넘게 못 보냈으면 버린다. 기록과 상태 파일에는 이름 대신 지문(보낼 사람 이름은 보낼 때까지만 상태 파일에), 안 될 때의 진단 파일에도 인사 글을 적지 않는다. 180일 넘게 안 보인 이름과 1년 지난 인사 기록은 지운다.
- 통계: 운영 분석(assets/ops-analyzer.js)의 봇 판정을 통계 화면과 같게(끝이 '-bot' 도 봇) 해서 봇 인사가 환영 비율에 들지 않는다.
- 확인할 것: 오픈채팅 태그 목록의 실제 모양. 태그가 안 되면 '@닉네임' 글로 나가므로, 그때 `greet study` 결과로 맞춘다.

## 2. 신입 첫 벙 챙기기 (입장 2주 안 첫 모임)

- 근거: 사이트 모임 글의 참석 명단. 참석 이름은 멤버 목록에서 고른 것이라 닉네임과 맞는다. 맞출 때 입장일 네 자리와 하트는 무시한다(운영 화면 '닉네임으로 멤버 찾기'와 같은 규칙).
- 7일째 아침: 닉네임에 입장일이 남아 있고 참석 기록이 없는 신입을 한 메시지에 모아 태그하고 이번 주 벙 링크를 붙인다. 방에 올릴지는 정할 것.
- 14일 넘김: 방에 올리지 않고 운영진 방에만 알린다.
- 선택, 날떼 안내: 첫 벙 다음 날 닉네임에서 입장일을 떼 달라고 태그한다(운영 방식에 맞을 때).
- 참석 명단은 실제 참석과 다를 수 있다(신청만 하고 오지 않음). 기한 넘김은 운영진이 확인한 뒤 조치한다.

## 3. 벙 참석자 태그

- 변경, 취소 알림에 참석자 태그: 지금 올리는 시간, 장소, 신청 마감 바뀜과 취소 알림에 그 벙 참석자를 태그한다. 메시지 수는 그대로다.
- 시작 전 태그: 시작 1시간 전(시각은 정함) 참석자를 태그하고 시간과 장소를 적는다. 벙 수만큼 메시지가 늘어서 켜고 끄기와 시각은 운영 화면에서 정한다.
- 1절의 태그 기능을 그대로 쓴다.

## 4. 운영진 보고 (운영진 방에만)

- 보낼 곳: 봇이 들어가 있는 운영진 방. 지금은 시험 방.
- 아침 보고: 09:00 '봇 정상' 줄에 더한다. 어제 들어옴, 나감, 이름 바꿈, 양식 틀림, 첫 벙 기한 다가옴과 넘김, 오늘 벙 수, 운영 화면 링크.
- 재입장 감시: 명단 이력을 서버에 쌓아 다시 들어온 사람, 재입장 한도(81 이하 1회, 82 이상 3회) 넘김, 내보낸 사람이 다시 들어옴을 찾자마자 알린다. SQL 한 번(명단 이력 표, 봇 열쇠로만 쓰기).
- 2개월 미참여: 주 1회 수만 보낸다(이름은 운영 화면). 방에는 올리지 않는다(사람을 지목한다).
- 이름은 운영진 방 글에만 쓰고 봇 기록 파일에는 적지 않는다.

## 5. 활성화 (선택)

- 자리 남은 오늘 벙 막판 알림: 시작 3시간 전 모집 중이고 자리가 남은 벙만 한 줄. 공지 카드에 이미 있고 ENGAGEMENT_PLAN 5-5의 '정기 자동 알림은 쓰지 않는다'와 겹쳐 뒤로 미룬다.
- 통계 발행 알림: 월간 통계를 발행하면 방에 링크 한 줄(지금은 운영진이 손으로 올린다).
- 키워드 자동응답(정산, 맛집, 규칙, 통계, 모임): 봇은 대화를 읽지 않으므로 카카오 방장봇 키워드로 한다(코드 없음, 방장이 앱에서 설정. ENGAGEMENT_PLAN 5-5).

## 6. 봇 관리

- 원격 새 판: 운영 화면 '새 판 받고 다시 켜기'. 봇이 1분 안에 읽고 저장소의 새 판을 받아 문법 검사 뒤 스스로 다시 켠다. 켜지 못하면 옛 판(.bak)으로 돌아간다. 1차 판에 넣으면 그 뒤 판은 태블릿을 만지지 않고 올린다.
- 운영 화면 '공지 다시 걸기' 단추.
- 운영 화면 봇 상태 자세히: 마지막으로 올린 글, 최근 실패, 보이스룸, 멤버 읽기 결과(지금은 마지막 확인 시각과 판만).
- 재부팅 뒤 자동 켜기: Termux:Boot. 무선 디버깅은 재부팅 뒤 손으로 켜야 할 수 있다.

## 7. 비속어 하루 보고

목적: 방의 욕설, 비속어 사용을 하루 단위로 세어 방에 수를 알리고, 구성원이 스스로 조심하게 한다. 사람을 지목하지 않는다.

### 7-1. 대화를 가져오는 방법

| 방법 | 내용 | 판단 |
|---|---|---|
| 대화 내보내기 | 하루 한 번 방 설정의 대화 내용 내보내기로 텍스트 파일을 태블릿 저장소에 저장하고 읽는다 | 권장. 빠짐이 없다. 단추 이름과 저장 위치는 태블릿에서 살핀다 |
| 알림 읽기 | 보이스룸처럼 dumpsys notification 으로 카카오톡 메시지 알림을 읽는다 | 글이 몰릴 때와 봇이 방을 연 동안 빠져 수가 틀린다 |
| 방 화면 읽기 | 대화를 밀어 올리며 화면 글을 읽는다 | 느리고 빠진다 |
| 운영진 파일 | 운영 화면에 대화 파일을 올릴 때만 센다(지금 운영 분석) | 매일 되지 않는다 |

- 내보내기는 텍스트만, 조용한 시간에 한다(05:10 멤버 읽기 뒤). 어제 하루만 센다. 파일에는 봇이 방에 들어온 뒤의 대화가 모두 들어 있다.
- 파일은 세자마자 지운다. 대화 글은 서버, 저장소, 기록 파일 어디에도 남기지 않는다. 남기는 것은 날짜별 수뿐이다.
- 읽는 법은 사이트 대화 파서(assets/chat-parser.js)의 안드로이드 양식을 파이썬으로 옮긴다.

### 7-2. 세는 기준

- 단어 목록: 운영 분석의 '욕설, 비하 표현' 목록(assets/ops-analyzer.js, 실제 오탐을 보고 좁힌 것)에서 시작한다. 운영 분석과 같은 목록을 쓴다.
- 가벼운 비속어(존나, ㅈㄴ, 졸라 등)를 셀지는 정할 것. 넣으면 수가 크게 는다.
- 숫자나 기호를 끼운 변형(시1발)은 잡는다. 띄어쓰기는 붙여 읽지 않는다(공시 발표 같은 오탐).
- 빼는 말 목록(시발점 등)을 둔다.
- 메시지 하나에 여러 번 써도 1건. 쓴 사람 수도 센다.
- 빼는 것: 봇 글, 시스템 줄(들어옴, 나감, 가림).

### 7-3. 방에 올리는 글

- 하루 한 번 정한 시각(예: 10:00)에 어제 하루(00:00~24:00) 수를 올린다.
- 전체 수만 올린다. 이름, 실제 단어, 원문은 올리지 않는다.
- 많다는 수만 보이면 '다들 쓴다'로 읽힐 수 있어, 전체 대화 수 가운데 비율과 0건인 날이 이어진 일수를 같이 보인다.
- 예(승인 전): "어제 대화 1,204건 중 비속어 3건(0.2%)이었어요. 최근 7일 11건."
- 0건인 날(예, 승인 전): "어제 대화 1,204건, 비속어 0건이에요. 4일째 0건."
- 문구는 한 가지로 고정한다(돌려 쓰지 않는다).
- 선택: 0건인 날은 올리지 않기, 하루 대신 주 1회.

### 7-4. 운영진에게만

- 운영진 방에 사람별 건수와 시각을 보낸다. 글은 넣지 않는다(운영진이 방에서 그 시각을 찾아 확인). 오탐일 수 있다.
- 일주일에 정한 수를 넘는 사람은 따로 표시한다. 조치(1차 구두 경고, 2차 운영진 면담, 3차 강제퇴장)는 운영진이 판단한다. 봇은 경고하거나 내보내지 않는다.

### 7-5. 알리기와 개인정보

- 시작 전에 방 공지나 규칙에 봇이 하루 한 번 비속어 수를 센다고 알린다(문구는 정할 것).
- 대화 파일은 태블릿 안에서만 읽고 바로 지운다. 서버에 올리지 않는다.
- 개인 이름을 방에 올리지 않는다. 사람을 지목하면 분위기가 나빠지고, 사실이어도 명예훼손 시비가 생길 수 있다.

### 7-6. 위험

- 감시받는 느낌: 매일 올라오는 경고 글은 피로하다. 비율과 이어진 일수로 부드럽게 쓰고, 필요하면 주 1회로 바꾼다.
- 피해 가기: 초성과 변형으로 피한다. 목록을 운영진이 고칠 수 있게 한다(운영 화면, 서버 설정).
- 오탐: 운영진 보고에서 확인한다.
- 화면 바뀜: 카카오톡 업데이트로 내보내기 단추가 바뀌면 그날은 방에 올리지 않고 운영진 방에 실패를 알린다.
- 원칙 바꿈: '대화 내용은 읽지 않는다'(0절)와 '정기 자동 알림은 쓰지 않는다'(ENGAGEMENT_PLAN 5-5)를 이 기능만큼 바꾼다. 만들 때 두 문서와 봇 설명을 같이 고친다.

### 7-7. 만들 것

- 봇: 내보내기 살피기(시험 방, 단추 이름과 저장 위치를 적음), 하루 한 번 내보내기와 세기와 지우기, 방에 올리기, 운영진 보고, 켜고 끄기와 시각(설정과 원격 조종).
- 시험: 지어낸 대화 파일로 센다(오탐, 변형, 빼는 말, 날짜 경계, 시스템 줄). 실제 대화는 저장소에 넣지 않는다.
- 선택: 운영 화면에서 단어 목록과 시각 고치기(SQL 한 번).

## 8. 자동화하지 않을 것

- 경고, 강제퇴장: 판단은 운영진, 봇은 알리기만.
- 대화 글을 서버나 저장소에 남기기.
- 개인별 비속어 수를 방에 공개하기.
- 정산 링크를 방에 올리기, 2개월 참여 기준 충족 여부 공개, 칭호 수상자 이름 올리기, 시간대 인사(ENGAGEMENT_PLAN 10절).

## 10. 정할 것

1. 신입 인사 문구(기본은 운영자 예시 그대로), 양식 줄과 링크를 붙일지.
2. 방장봇 입장 메시지를 쓰는지(쓰면 1절과 겹친다).
3. 첫 벙 안내를 방에서 태그할지, 운영진 방에만 알릴지.
4. 시작 전 참석자 태그를 켤지와 시각.
5. 비속어: 가벼운 비속어를 셀지, 올리는 시각, 0건인 날도 올릴지, 하루와 주 1회 중 무엇으로 할지.
6. 비속어: 방 공지(규칙)에 알리는 문구.
7. 운영진 방: 시험 방을 그대로 쓸지, 운영진 방을 따로 만들지.
