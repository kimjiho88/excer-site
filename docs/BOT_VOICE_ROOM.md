# 봇의 보이스룸 지키기 설계 (2026-10-02, 설계안)

상태: 1단계 구현됨(2026-10-02). `voice study`, `voice status`, `voice on`, `voice off`, 그리고 `run` 안의 끊김 기록. 2단계(복구, 48시간 갱신, 자물쇠)는 study 결과로 단추 이름을 확정한 뒤 만든다.

목적: 봇 계정(excer-bot)이 방 홍보용으로 켜 두는 오픈채팅 보이스룸이 간혹 끊긴다. 봇이 끊김을 스스로 알아채고 다시 켠다. 공지 봇(벙 일정 올리기)과 같은 태블릿, 같은 파이썬에서 함께 돈다.

## 1. 확인한 사실 (카카오 공개 자료)

- 만들기: 오픈채팅방 왼쪽 아래 `+` 메뉴의 보이스룸. 그룹 오픈채팅방에서 방장과 부방장만 만든다. 최대 1,500명.
- 참여: 방 안의 보이스룸 말풍선이나 방 위쪽 띠의 '참여' 단추.
- 역할: 진행자(방장, 부방장), 스피커, 리스너.
- 종료: 유일한 진행자가 나가거나, 만든 지 48시간이 지나면 끝난다. 진행자가 아닌 방장은 남의 보이스룸을 끝내지 못한다.
- 백그라운드: 다른 앱을 쓰거나 화면을 꺼도 유지된다. 보이스룸 알림을 끄고 켜는 설정이 따로 있다.
- 아직 모르는 것(태블릿에서 적어야 한다, 4절의 study): 보이스룸 화면 단추의 정확한 이름(마이크, 최소화, 나가기, 종료), 만들 때 제목 창이 있는지, 방 위쪽 띠의 글자(봇이 참여 중일 때와 아닐 때), 알림 창의 글자, 다른 앱 위에 뜨는 작은 창이 있는지, 끊겼을 때 뜨는 안내 창.

## 2. '튕김' 의 뜻

봇 계정이 보통 유일한 진행자다. 그래서 봇이 떨어지면 보이스룸 자체가 끝난다. 복구는 대부분 '다시 들어가기' 가 아니라 '새로 만들기' 다.

| 종류 | 원인 | 봇의 대응 |
|---|---|---|
| 만료 | 만든 지 48시간 | 예정된 종료. 47시간 30분에 봇이 먼저 끝내고 새로 만든다(몇 초 빈다) |
| 연결 끊김 | 와이파이 재접속, IP 바뀜, 통신 불안 | 끊김을 알아채면 새로 만든다 |
| 앱 죽음 | 메모리 부족, 배터리 최적화, 앱 업데이트 | 카카오톡을 다시 켜고 새로 만든다 |
| 사람의 뜻 | 다른 진행자가 끝냄, 봇이 내보내짐 | 바로 다시 만들지 않는다. 설정한 시간 뒤 한 번만(기본은 안 함) |
| 봇 실수 | 공지 작업 중 보이스룸 창의 '나가기' 를 누름 | 5절: 작업 흐름에서 그 창을 피하고 금지 단어를 누르지 않는다 |

## 3. 감지: 지금 켜져 있는지

화면을 건드리지 않고 adb 로 세 신호를 읽는다. 60초마다.

1. 알림: `dumpsys notification --noredact` 에서 `com.kakao.talk` 의 진행 중(ongoing) 알림에 '보이스룸' 글자. 카카오톡은 통화 계열 기능을 포그라운드 서비스로 돌리므로 알림이 있다. 가장 믿을 만한 신호.
2. 소리: `dumpsys audio` 의 players 에 `com.kakao.talk` 가 started. 리스너라도 수신 스트림이 돈다.
3. 서비스: `dumpsys activity services com.kakao.talk` 의 통화 계열 서비스(이름은 study 로 적는다).

판정: 1이 있으면 켜짐. 1이 없고 2와 3도 없으면 꺼짐. 두 번 연속 꺼짐(약 2분)이면 복구를 시작한다. 신호가 엇갈리면(알림 없음, 소리 있음) 방을 열어 위쪽 띠를 읽고 확정한다.

기록: 켜진 시각, 꺼진 시각, 그때 카카오톡 프로세스가 살아 있었는지(`pidof com.kakao.talk`), 네트워크 상태(`dumpsys connectivity` 의 활성 연결 한 줄), 만든 지 몇 시간째였는지를 `excer_bot.log` 와 `excer_bot_voice.json` 에 남긴다. 튕기는 시각의 규칙(매번 48시간, 새벽 와이파이 절전, 특정 시각)을 찾는 근거다.

## 4. 복구 절차

같은 자물쇠를 쓴다. 공지 작업 중이면 끝난 뒤에, 복구 중이면 공지는 기다린다.

1. 화면을 켜고 카카오톡을 앞으로(지금의 launch). 카카오톡이 죽어 있으면 그대로 켜진다.
2. 보이스룸 화면이나 안내 창(연결이 끊겼습니다 등)이 떠 있으면 확인 단추로 닫는다. '나가기', '종료' 는 누르지 않는다.
3. 방을 연다(지금의 open_room).
4. 방 위쪽에 보이스룸 띠가 있고 '참여' 가 보이면 참여한다(다른 진행자가 열어 둔 것). 들어간 뒤 마이크가 켜져 있으면 끈다.
5. 띠가 없으면 새로 만든다: `+` 메뉴, 보이스룸, (제목 창이 있으면 설정의 제목), 시작. 마이크 끄기. 마이크 권한 창이 뜨면 허용(처음 한 번).
6. 확인: 3절의 신호 1(알림)이 생겼는지. 안 생겼으면 화면을 `excer_bot_ui.txt` 에 적고 실패로 친다.
7. 보이스룸 화면을 최소화(뒤로 가기 또는 최소화 단추, study 로 확인)하고 Termux 로 돌아온다(return_to).

재시도: 실패하면 1분, 2분, 5분, 10분, 15분 간격(최대 15분)으로 계속한다. 성공하면 간격을 처음으로. 연속 다섯 번 실패하면 로그에 크게 남기고, 설정이 켜져 있으면 시험 방에 한 줄 보낸다(사람이 알 수 있게).

사람의 뜻: 띠가 있는데 '참여' 가 아니라 내보내진 상태로 보이면(글자는 study 로 확인) 다시 들어가지 않는다. 설정 `kick_retry_min` 이 0보다 크면 그 시간 뒤 한 번만 시도한다.

소리: 봇은 늘 마이크 끔. 통화 음량은 0(`cmd media_session volume --stream 0 --set 0`, 안 되면 `media volume --stream 0 --set 0`). 태블릿 스피커로 방 소리가 나지 않게 한다.

## 5. 공지 작업과의 충돌

- 보이스룸이 켜져 있으면 방 위쪽에 띠가 생겨 말풍선이 아래로 밀린다. 지금의 공지 방식은 자리가 아니라 글자로 찾으므로 영향이 없다(freeze, find_own).
- 다른 앱 위에 뜨는 작은 창이 있다면 입력 칸이나 말풍선을 가릴 수 있다. open_room 뒤 그 창이 보이면 먼저 치운다(끌어 옮기기 또는 최소화). 위치와 글자는 study 로 적는다.
- 보이스룸 화면이 앞에 뜬 채로 공지 차례가 오면 뒤로 가기 한 번으로 방으로 돌아온다. 금지 단어 목록('나가기', '종료', '보이스룸 나가기', '방 나가기')은 어떤 흐름에서도 누르지 않는다.
- 복구 뒤에는 공지 흐름이 쓰는 '방이 열려 있음' 판정(room_open)이 띠 때문에 흔들리지 않는지 확인한다(방 이름 머리의 위치 기준 12% 안).

## 6. 48시간 갱신

- 만든 시각을 기록한다. `renew_hours`(기본 47.5)가 지나면 봇이 스스로 끝내고(나가기 뒤 종료 확인, 글자는 study 로) 바로 새로 만든다. 홍보 노출이 몇 초 끊긴다.
- 조용한 시간대(`quiet`)에는 갱신하지 않고 그 시간이 끝난 뒤 한다. 끊김 복구는 조용한 시간대에도 한다(설정으로 끌 수 있다).
- 새로 만들 때마다 방 참가자에게 보이스룸 알림이 갈 수 있다. 하루에 만드는 횟수 한도(`max_new_per_day`, 기본 6)를 두고, 넘으면 다음 날까지 복구를 멈추고 로그에 남긴다.

## 7. 기기 설정: 튕김 자체를 줄이기

- 카카오톡 배터리: 제한 없음. 삼성이면 '사용하지 않는 앱 절전' 에서 카카오톡과 Termux 제외.
- 와이파이: 절전 모드 끔, 화면이 꺼져도 와이파이 유지.
- 카카오톡 알림 권한과 보이스룸 알림을 켜 둔다. 꺼져 있으면 3절의 신호 1이 보이지 않는다.
- 플레이스토어 자동 업데이트는 끄거나 야간으로. 업데이트 중 앱이 죽어도 봇이 다시 만들지만, 업데이트 뒤 화면 글자가 바뀌면 study 를 다시 돌린다.
- 개발자 옵션: '활동 유지 안 함' 끔, 백그라운드 프로세스 제한은 표준.
- 지금 하는 것 그대로: 화면 잠금 없음, 충전기, Termux wake lock.

## 8. 설정과 명령

`excer_bot.json` 에 `voice` 묶음을 더한다.

```json
"voice": {"on": false, "room": "", "title": "", "check_sec": 60, "renew_hours": 47.5, "mute": true,
          "max_retry_min": 15, "kick_retry_min": 0, "max_new_per_day": 6, "alert_test_room": false}
```

`room` 이 비어 있으면 공지 방(`room`)과 같은 방이다.

| 명령 | 하는 일 |
|---|---|
| `python excer_bot.py voice study` | 시험 방에서 한 번 해 본다: 만들기, 보이스룸 화면, 최소화, 방의 띠, 알림과 서비스와 소리 신호, 다시 열기, 나가기와 종료 확인 창. 단계마다 화면 글자를 `excer_bot_study.txt` 에 적고 클립보드에 담는다. 이 결과로 단추 이름을 확정한다 |
| `python excer_bot.py voice status` | 지금 켜져 있는지(세 신호), 만든 지 몇 시간째인지, 최근 끊김 기록 |
| `python excer_bot.py voice now` | 지금 바로 복구 절차를 한 번 돌린다(시험용) |
| `python excer_bot.py voice on` / `off` | 설정을 켜고 끈다 |
| `python excer_bot.py run` | `voice.on` 이면 공지 감시와 함께 보이스룸 감시도 돈다 |

## 9. 만드는 차례

1. `voice study` 와 감지 신호 셋 읽기, `voice status`. 화면은 건드리지 않는 부분이라 바로 쓸 수 있다.
2. study 결과로 단추 이름과 띠 글자를 확정하고 복구 절차, 48시간 갱신, 공지 흐름과의 자물쇠.
3. 흉내 시험(가짜 dumpsys 출력과 가짜 화면으로 끊김, 앱 죽음, 만료, 내보내짐, 공지 중 끊김)과 시험 방 실측.
4. 운영 방에 켜고 일주일 기록을 본다. 끊김 원인별로 7절의 기기 설정과 재시도 간격을 조정한다.

## 10. 한계

- 카카오톡 화면 글자가 바뀌면 복구 절차가 멈출 수 있다. 그때는 신호 1로 끊김은 알아채되 복구는 실패 로그만 남는다. study 를 다시 돌려 글자를 맞춘다.
- 다른 사람이 만든 보이스룸에 봇이 리스너로만 들어가 있는 경우, 그 사람이 나가면 끝난다. 봇이 진행자가 되려면 봇이 만들어야 한다.
- 48시간 갱신 때 몇 초, 끊김 때 최소 2분에서 수 분은 비어 있다. 끊김 없는 유지는 카카오톡 구조상 할 수 없다.
