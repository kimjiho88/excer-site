# 운영 대시보드 기획 (내부 문서, 배포 제외)

2026-09-25, 23차. 운영진만 쓰는 비공개 페이지. 카카오톡 대화 내보내기 파일에서 확인할 수 있는 데이터를 모두 분석해 구성원 관리(규칙 점검, 조치 기록, 신입과 장기 미참여 관리)에 쓴다. 공개 활동 통계와는 목적이 다르다. 공개 통계는 모두가 보는 요약이고, 이 페이지는 운영진이 사람을 관리하는 도구다.

## 2. 대화 내보내기에서 얻을 수 있는 것과 없는 것

- **얻을 수 있음**: 메시지마다 날짜, 시각, 그때의 닉네임, 종류(글, 사진, 동영상, 이모티콘, 파일, 음성, 링크, 삭제된 메시지), 글 내용. 시스템 줄: 들어옴, 나감, 내보냄(누가 내보냈는지 포함되는 꼴도 있음), 가려진 메시지, 공지 등록.
- **얻을 수 없음**: 모임 참석 여부(캘린더 참석 버튼 기록은 내보내기에 없음으로 보이며, 실제 파일로 확인 필요), 투표 결과, 1:1 대화, 프로필 사진, 기혼 여부, 방장봇 안내 문구 외의 운영진 조치.
- **한계**: 내보낸 기기에 남아 있는 기간만 담긴다. 닉네임을 바꾸면 같은 사람이 다른 이름으로 보인다(발행 화면의 '같은 사람 합치기'와 같은 기억을 쓴다). 들어올 때의 이름은 양식 전 이름일 수 있어 재입장은 '추정'이고 운영진이 확인한다.
- **다른 자료**: 사이트의 모임 정산(날짜와 참여자 이름, 120일 보관), 소식의 모임 모집 글과 후기(날짜, 작성자). 참석 기록의 보조 자료로 쓸 수 있다.

## 3. 페이지 구성

### 3-1. 한눈에 (첫 화면)
- 현재 인원(파일 기준 방에 있는 사람), 이번 달 들어옴, 나감, 내보냄, 순증.
- **확인할 사람** 대기열: 아래 점검에 걸린 사람을 한 목록으로. 한 사람에 걸린 항목을 모아 보이고, '확인함'으로 넘기면 다음 파일에서 새로 걸릴 때만 다시 뜬다.
- 신입 목록: 입장 며칠째, 첫 대화 여부, 첫 모임 기록 여부(2단계).

### 3-2. 멤버 원장 (한 사람 한 줄)
- 지금 닉네임, 예전 닉네임들, 실제 입장일(들어옴 기록), 닉네임의 입장일, 상태(방에 있음, 나감, 내보냄), 재입장 횟수, 닉네임 변경 횟수, 메시지 수(최근 30, 60, 90일), 마지막 대화일, 삭제한 메시지 수, 조치 기록, 메모, 예외(장기 미참여 알림, 재입장 예외).
- 찾기, 보기(방에 있음, 나간 사람, 내보낸 사람, 신입, 조치 있음), 정렬, 명단 내보내기(CSV).
- 사람 상세: 활동 추이(주별 메시지), 들어옴과 나감 이력 타임라인, 닉네임 이력, 조치 이력, 메모.

### 3-3. 규칙 점검
1. **닉네임 양식**: 다섯 칸, 순서, 출생연도 두 자리, 입장일 네 자리, 성별 남 또는 여. 이름만, 칸 누락, 이모지만인 사람. 닉네임의 입장일과 실제 들어온 날이 다르면 표시(재입장 뒤 예전 입장일을 그대로 쓰는 경우).
2. **닉네임 변경 횟수**: 같은 사람으로 묶인 닉네임이 둘 이상이면 변경. 2회 이상이면 표시. 바뀐 날짜 표시.
3. **재입장 횟수**: 나감(또는 내보냄) 뒤 같은 사람(앞 이름, 성별, 출생연도가 같은 닉네임)이 다시 들어온 횟수. 출생연도 기준 한도(81년생 이전 1회, 82년생 이후 3회)를 넘으면 표시. 예외로 기록한 사람은 제외. 내보낸 사람이 다시 들어오면 따로 표시.
4. **처음 2주**(2단계): 입장 14일이 지났는데 첫 모임 기록이 없는 사람. 그 전에는 남은 날 수만 표시.
5. **정기 참여**(2단계): 마지막 모임 기록이 60일을 넘은 사람. 예외 기간이 있으면 제외. 대화도 없는 사람은 따로 묶는다.
6. **메시지 삭제**: 기간 내 '삭제된 메시지입니다'가 잦은 사람(기준 횟수는 운영진이 정함).
7. **신호(참고용)**: 다른 오픈채팅 링크(open.kakao.com)를 올린 사람, 전화번호 모양(010 과 숫자 여덟 자리)을 올린 사람, '비벙', '후일담' 언급. 판단하지 않고 날짜와 해당 줄만 운영진에게 보여 준다(원문은 이 기기 밖으로 나가지 않는다).

### 3-4. 조치 기록
- 사람마다 조치 추가: 종류(금지 행동, 비벙), 단계(구두 경고, 면담, 강제퇴장), 날짜, 사유, 운영진 메모.
- 규칙의 조치 단계에 맞춰 '다음 단계'를 보여 준다(금지 행동 1차 경고 뒤 재적발이면 강제퇴장, 비벙은 경고, 면담, 강제퇴장).
- 강제퇴장한 사람이 다시 들어오면 한눈에 대기열 맨 위에.

### 3-5. 참석 기록 (2단계)
- 모임마다 참석자 체크(날짜, 모임 이름, 참석자). 멤버 원장의 이름 목록에서 고른다.
- 보조 자료로 가져오기: 모임 정산의 날짜와 참여자 이름(앞 이름으로 맞추고 애매하면 운영진이 고름), 소식의 모임 모집 글과 후기.
- 이 기록으로 처음 2주, 정기 참여 점검을 켠다.

### 3-6. 흐름 분석 (3단계)
- 월별 들어옴, 나감, 순증과 남아 있는 비율(입장 후 30, 60, 90일에 방에 남아 있는 비율).
- 신입 흐름: 입장, 첫 대화, 첫 모임, 2개월 뒤 유지까지의 단계별 인원.
- 들어온 지 7일 안에 나간 사람 수(첫인상 지표), 입장 후 첫 대화까지 걸린 날.
- 대화가 줄어든 사람(최근 30일이 이전 60일 평균보다 크게 줄어든 사람), 환영 인사를 자주 하는 사람.

## 4. 데이터와 보안

- **원문은 올리지 않는다**: 대화 파일은 지금 발행 화면처럼 이 브라우저 안에서만 읽는다. 서버로 보내지 않는다.
- **기록 저장**: 조치, 메모, 예외, 참석, 같은 사람 묶음, 확인함 표시를 어디에 둘지 운영자가 정한다.
  - 가. 이 기기 브라우저에만 저장, 파일로 백업과 복원(서버에 아무것도 없음, 기기를 잃으면 백업 파일로 복구).
  - 나. 서버의 비공개 표에 저장, 운영진 비밀번호로만 읽고 쓰기(여러 기기에서 같은 기록, 새 SQL 필요, 비밀번호가 새면 기록도 샌다).
  - 추천: 가로 시작하고, 여러 기기가 필요해지면 나.
- **페이지 접근**: 운영진 비밀번호를 서버에서 확인해야 열린다(발행 화면과 같은 방식). 사이트 어디에도 링크하지 않고, 운영진 기기의 발행 화면에서만 들어가는 길을 둔다. 검색 제외(noindex), 사이트맵 제외.
- **공개 통계와 분리**: 나감, 내보냄, 재입장, 조치, 신호는 공개 통계에 절대 싣지 않는다.
- **같은 사람 묶음 공유**: 발행 화면에서 합친 사람과 대시보드의 같은 사람 묶음은 같은 기억을 쓴다.

## 5. 단계

1. **1단계(서버 변경 없음)**: 페이지와 비밀번호 확인, 대화 파일 올리기(여러 파일, 겹침 정리, 읽지 못한 줄 목록), 멤버 원장, 한눈에(인원 변화, 확인할 사람), 규칙 점검 1, 2, 3, 6, 7, 조치 기록, 이 기기 저장과 백업, 복원.
2. **2단계**: 참석 기록(수기 체크, 정산과 소식 가져오기)과 처음 2주, 정기 참여 점검. 정산 참여자를 읽으려면 운영진 비밀번호로 최근 정산 목록을 돌려주는 새 SQL 이 필요하다.
3. **3단계**: 흐름 분석, 서버 저장(선택), 운영진 여러 명 공유(선택).

## 6. 운영자가 정할 것

1. 기록 저장 위치: 이 기기만(백업 파일) 또는 서버(운영진 비밀번호)
2. 참석 기록 방법: 모임마다 운영진이 체크, 모임 정산 참여자 가져오기, 둘 다
3. 신호(다른 방 링크, 전화번호 모양, 비벙 언급)를 대기열에 올릴지
4. 메시지 삭제 기준 횟수(예: 30일에 5회 이상)
5. 대시보드를 운영진 3명이 함께 쓸지, 운영자만 쓸지(지금 운영진 비밀번호는 운영자만 앎)
6. 재입장 한도 판정에 쓰는 출생연도는 닉네임의 두 자리로 본다(예: 81 이하는 1회). 맞는지
