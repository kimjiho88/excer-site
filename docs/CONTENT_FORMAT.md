# 콘텐츠 양식 (내부 문서, 배포 제외)

같은 종류의 글은 같은 자리에서 같은 순서로 정보를 찾을 수 있어야 합니다. 이 문서는 맛집과 소식의 저장 구조, 표시 항목과 순서, 없는 항목의 처리, 기존 글의 정리 방식, 등록·수정 화면의 규칙, 용어 사전을 정합니다. 화면 코드는 이 문서를 따릅니다(`assets/content.js`).

## 0. 원칙

콘텐츠는 세 종류로 나눕니다.

| 종류 | 예 | 처리 |
|---|---|---|
| A. 사실 정보 | 식당명, 지역, 종류, 가격, 날짜, 장소, 인원, 신청 방법 | 항목으로 분리해 같은 순서로 표시. 없으면 채우지 않음 |
| B. 작성자의 평가와 경험 | 추천 메뉴, 한줄평, 방문 팁, 후기 본문 | 의미와 말투를 지키며 읽기 좋게만 정리. 강도·범위를 바꾸지 않음 |
| C. 서비스 안내 | 버튼, 도움말, 오류, 필터 설명, 정책 설명 | 사이트 전체 문구 기준으로 통일 |

편집 규칙(B에 적용):

- 작성자의 의견을 사실로 바꾸지 않습니다. "냉면은 저는 그냥 그랬어요" → "냉면은 개인적으로 평범했습니다." (○) / "냉면 비추천" (×)
- 단순 언급을 "대표 메뉴", "인기 메뉴", "시그니처"로 바꾸지 않습니다. 작성자가 적은 메뉴는 "추천 메뉴"로만 둡니다.
- 없는 사실을 더하지 않습니다(주소, 영업시간, 휴무일, 예약 가능 여부, 가격).
- 정리한 문장은 편집문입니다. 인용부호를 붙이지 않습니다. 원문은 상세의 작성 정보에서 볼 수 있습니다.
- 같은 문장을 목록·상세·팁 세 곳에 반복하지 않습니다. 정보마다 자리를 하나 정합니다.

## 1. 맛집

### 1.1 저장 구조 (Supabase)

| 표 | 칸 | 뜻 |
|---|---|---|
| site_places | name(≤40) | 식당명. 지점명은 이름 안에 씁니다("마담밍 선릉점"). 별도 칸 없음 |
| | area | 표시용 지역. 값: 논현/신사 · 역삼/선릉 · 강남역 · 압구정/청담 · 삼성/대치 · 서초/교대 · 도곡/양재 · 잠실/송파 · 그 외 |
| | area_detail(≤30) | 위치 보조. 도로명 주소("역삼로 164")나 실제 동네("용산 이태원") |
| | category | 음식 종류. 고기 · 한식 · 일식 · 중식 · 양식/퓨전 · 술집/포차 · 카페/디저트 · 분식/면 |
| | price_level 1~4, price_note(≤30) | 1인 가격대(주류 제외)와 메모 |
| | map_url(≤400) | 지도 링크. 없으면 "지역 첫 단어 + 식당명"으로 카카오맵 검색 |
| | closed | 영업 종료 표시(삭제 대신) |
| | author, created_at | 등록자, 등록일 |
| site_place_notes | body(≤120) | 한줄평(작성자의 평가) |
| | menu(≤40) **신규** | 추천 메뉴. 작성자가 적은 메뉴만 |
| | tip(≤120) **신규** | 방문 팁·유의사항. 작성자가 적은 것만 |
| | again | 재방문 의사 |
| | visit_date, per_person | 실제 방문일, 1인 금액(선택) |
| | author, created_at | 작성자, 작성일 |

신규 칸은 `sql/2026-09-24-content-format.sql`로 추가합니다. 서버가 아직 이전 형식이면 화면은 한줄평 한 칸만 받고, 그 사실을 폼에 표시합니다(`site_schema_v` 조회로 판단).

### 1.2 표시 항목

| 항목 | 출처 | 없을 때 |
|---|---|---|
| 식당명 | name | — (필수) |
| 지점명 | 이름 안의 "○○점" | 따로 표시하지 않음 |
| 표시용 지역 | area ("그 외" → "그 외 지역") + area_detail | area_detail 없으면 지역만 |
| 주소 | area_detail 이 도로명·번지 꼴("…로 164", "…길 6")일 때 상세의 위치 항목에 | 생략 |
| 음식 종류 | category | — (필수) |
| 1인 가격 | price_level → "1인 1만원 이하 / 1만원대 / 2만원대 / 3만원 이상", price_note 는 괄호 | 목록·상세 모두 "가격 미등록" (비교에 중요한 누락이므로 표시) |
| 추천 메뉴 | 한줄평들의 menu 를 중복 없이 모음 | 항목 생략 |
| 한줄평 | 가장 최근 한줄평의 정리본(review) 또는 원문(body) | 목록: "한줄평 없음", 상세: 한줄평 남기기 유도 |
| 방문 팁 | 한줄평들의 tip | 항목 생략 |
| 작성자 | 한줄평의 author | 한줄평이 없으면 등록자(author)를 작성 정보에만 |
| 등록일 | site_places.created_at | 상세 작성 정보에만 |
| 방문일 | 한줄평의 visit_date | 값이 있을 때만. 등록일과 섞지 않음 |
| 지도 링크 | map_url 또는 카카오맵 검색 | 항상 있음(검색 링크) |

**목록 한 줄(행)의 순서**

1. 식당명 (+ 영업 종료 / 방문 N회 표시)
2. 지역 · 음식 종류
3. 가격
4. 한줄평 (추천 메뉴가 있으면 앞에 "추천 메뉴" 한 줄, 한줄평이 없고 메뉴만 있으면 메뉴만)
5. 작성자 (· 방문일)
6. 상세 열기 · 지도에서 보기

**상세의 순서**

1. 식당명과 기본 정보 — 지역(위치 보조 포함), 종류, 가격(메모), 영업 상태
2. 추천 메뉴
3. 방문 후기 — 한줄평 전부(작성자, 방문일, 1인 금액, 재방문 의사). 재방문 의사 비율은 2건 이상일 때만
4. 방문 팁
5. 위치와 지도 — 주소(있을 때), 지도 링크
6. 작성 정보 — 등록자, 등록일, 정리한 한줄평의 원문(있을 때)

정보가 없는 항목은 제목째 생략합니다. "미등록"을 줄줄이 적지 않습니다(가격만 예외).

### 1.3 기존 한줄평의 정리본

- 파일: `data/places-curated.json`. 저장소에 두고 화면이 읽습니다. 서버 데이터는 바꾸지 않습니다.
- 키: 식당명(공백 제거·소문자) + 지역(가운뎃점은 빗금으로) + 한줄평 원문(앞뒤 공백 제거, 완전 일치).
- 적용 조건: 서버의 한줄평에 menu·tip 이 없고, 원문이 정리본의 original 과 같을 때만. 작성자나 운영진이 한줄평을 수정하면 원문이 달라지므로 정리본은 자동으로 빠집니다.
- 우선순위: **작성자가 수정한 내용(서버 menu/tip/body) > 정리본 > 원문**.
- 되돌리기: 파일에서 항목을 지우면 원문으로 돌아갑니다. 몇 번을 다시 적용해도 결과가 같습니다(화면에서 병합만 하고 저장하지 않음).
- 정리 대기: 안전하게 나누기 어려운 글은 `status: "pending"` 으로 두고 원문을 그대로 보여 줍니다.
- 검증: `scratchpad/curate-check.js` 가 seed 와 대조해 매칭 건수·불일치·중복을 출력합니다.

### 1.4 편집 예시 (실제 데이터)

| 원문 | 추천 메뉴 | 한줄평 | 방문 팁 |
|---|---|---|---|
| 냉짬뽕 맛집 (매운맛 단계별로 고를 수 있어요) | 냉짬뽕 | 냉짬뽕을 추천합니다. | 매운맛 단계를 선택할 수 있습니다. |
| 갈비찜이 맛있어요. 냉면도 맛있다는데 저는 그냥 그랬어요 | 갈비찜 | 갈비찜은 맛있었고, 냉면은 개인적으로 평범했습니다. | — |
| 들기름 막국수 | 들기름 막국수 | — (메뉴만 적힌 글. 목록에는 추천 메뉴만 표시) | — |

## 2. 소식

### 2.1 저장 구조

`site_posts`: category · title(≤100) · body(≤4000) · author · pinned · meta(jsonb) · created_at · updated_at. 댓글은 `site_comments`, 반응은 `site_post_reactions`.

카테고리 저장값과 표시명:

| 저장값 | 표시명 | 양식 |
|---|---|---|
| 공지 | 공지 | 운영진만. 목록 맨 위 고정 |
| 벙 소식 | 모임 모집 | 날짜 있는 글은 홈의 다가오는 모임에 |
| 후기 | 모임 후기 | |
| 정보 | 정보 | |
| 자유 | 자유 | |

### 2.2 유형별 항목 (meta 키)

서버 정리기 `post_meta_clean(category, meta)` 가 아는 키만 남기고 길이·형식을 검사합니다. 아래 표의 키만 저장됩니다.

| 유형 | 항목 | meta 키 | 형식 | 필수 |
|---|---|---|---|---|
| 공지 | 핵심 안내 | summary | ≤120자 | 선택 |
| | 적용 대상 | audience | ≤40자 | 선택 |
| | 적용일 · 종료일 | from, to | YYYY-MM-DD | 선택 |
| | 필요한 행동 | action | ≤80자 | 선택 |
| 모임 모집 | 모임명 | (title) | | 필수 |
| | 날짜 · 시간 | date, time | YYYY-MM-DD, HH:MM | 날짜 권장 |
| | 장소 | place | ≤60자 | 선택 |
| | 모집 인원 | cap | 1~200 | 선택 |
| | 예상 비용 | cost | ≤40자 | 선택 |
| | 모임장 | (author) | | 필수 |
| | 신청 방법 | apply | ≤80자, 기본값 "오픈채팅 공지의 참석 버튼" | 선택 |
| | 준비물 · 유의사항 | bring | ≤120자 | 선택 |
| | 모집 상태 | status | recruiting / closed. 모임장이 직접 바꿀 때만 | 선택 |
| 모임 후기 | 모임 또는 활동 종류 | activity | ≤40자 | 선택 |
| | 날짜 · 장소 | date, place | | 선택 |
| | 관련 링크 | link | http(s) URL ≤400 | 선택 |
| 정보 | 핵심 내용 | summary | ≤120자 | 선택 |
| | 관련 링크 · 출처 | link, source | URL, ≤60자 | 선택 |
| | 유효 기간 | until | YYYY-MM-DD | 선택 |
| 자유 | — | (meta 없음) | | |

모임 모집의 kind 는 기존과 같이 `bung` 입니다(기존 글 호환). 공지는 `notice`, 후기는 `review`, 정보는 `info`.

### 2.3 목록 표시 (제목 중심)

한 행: `[유형] 제목` / 보조 한 줄: 작성자 · 날짜 · 댓글 수 · 반응 수. 유형별 보조 정보:

- 모임 모집: 모임 날짜 (D-day) · 시간 · 장소 (있는 것만). 날짜가 지나면 "지난 모임".
- 공지: 적용일이 있으면 "9월 1일부터".
- 정보: 유효 기간이 있으면 "9월 30일까지".
- 후기·자유: 본문 첫 줄 요약.

### 2.4 상세 표시 순서

- 공지: 핵심 안내 → 적용 대상 · 적용 기간 · 필요한 행동(있는 것만, 표 형태) → 상세 내용(본문)
- 모임 모집: 날짜·시간 → 장소 → 모집 인원 · 예상 비용 → 모임장 → 신청 방법 → 준비물·유의사항 → 본문 → 오픈채팅 버튼
- 모임 후기: 활동 종류 · 날짜 · 장소 → 후기 본문 → 관련 링크
- 정보: 핵심 내용 → 본문 → 관련 링크 · 출처 · 유효 기간
- 자유: 본문

기존 글(meta 없음)은 제목과 본문만 표시합니다. 없는 항목을 만들어 채우지 않습니다.

## 3. 등록·수정 화면 규칙

- 유형을 먼저 고르면 그 유형의 항목만 보입니다. 필수는 제목·본문(모집은 날짜 권장), 나머지는 "선택" 표시.
- 제목·장소·가격·본문을 한 칸에 몰아넣지 않습니다.
- 예시는 placeholder 와 도움말로만 씁니다. 입력값으로 미리 넣지 않습니다.
- 저장 전 미리보기: 목록 행과 상세가 실제 표시대로 보입니다.
- 오류는 해당 항목 아래에 표시하고 첫 오류 항목으로 포커스를 옮깁니다. 서버 오류가 나도 입력값은 남깁니다.
- 기존 글도 같은 폼으로 수정합니다. 맛집 한줄평은 정리본이 있으면 수정 폼에 정리본을 미리 채워, 저장하면 서버 값이 됩니다(그 뒤로는 서버 값이 우선).
- 글자 수 제한은 서버 제약(제목 100, 본문 4000, 한줄평 120, 팁 120, 메뉴 40)만 둡니다. 화면에 맞추려고 자르지 않습니다.
- AI 자동 정리 같은 실제로 없는 기능은 만들지 않습니다.

## 5. 문구 기준 (요약)

- 짧고 자연스러운 존댓말. 모든 문장을 "입니다"로 끝내지 않습니다.
- 제목은 목적이 분명한 명사나 짧은 문장. 설명은 화면에서 바로 알 수 없는 정보만.
- 버튼은 실제 행동. 성공은 완료된 사실("글을 저장했습니다."). 오류는 문제와 해결 방법.
- 쓰지 않는 표현: 근거 없는 시간 약속, 과장("완벽하게", "누구나 바로"), 감정 유도, 화면 설명 반복("여기에서 확인할 수 있습니다"), 내부 용어, 뜻이 불분명한 "완료·확인·진행".
