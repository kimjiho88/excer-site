# 콘텐츠 양식 (내부 문서, 배포 제외)

같은 종류의 글은 같은 자리에서 같은 순서로 정보를 찾을 수 있어야 합니다. 이 문서는 맛집과 소식의 저장 구조, 표시 항목과 순서, 없는 항목의 처리, 기존 글의 정리 방식, 등록·수정 화면의 규칙, 용어 사전을 정합니다. 화면 코드는 이 문서를 따릅니다(`assets/content.js`).

## 0. 원칙

콘텐츠는 세 종류로 나눕니다.

| 종류 | 예 | 처리 |
|---|---|---|
| A. 사실 정보 | 식당명, 지역, 종류, 가격, 날짜, 장소, 인원, 신청 방법 | 항목으로 분리해 같은 순서로 표시. 없으면 채우지 않음 |
| B. 작성자의 평가와 경험 | 추천 메뉴, 한줄평, 방문 팁, 후기 본문 | 의미와 말투를 지키며 읽기 좋게만 정리. 강도·범위를 바꾸지 않음 |
| C. 서비스 안내 | 버튼, 도움말, 오류, 필터 설명, 정책 설명 | 사이트 전체 문구 기준으로 통일 |

편집 규칙(B에 적용):

- 정리는 "자리 나누기"입니다. 원문을 추천 메뉴·한줄평·방문 팁 자리로 나누고, 말투는 원문 그대로 둡니다. 맞춤법·띄어쓰기만 고칩니다("덕자찜 레전드집" → "덕자찜 레전드 집").
- 원문 끝에 "입니다"를 붙이거나 존댓말로 바꾸지 않습니다. "밥도둑 술도둑" 은 그대로 "밥도둑 술도둑". "간장게장 1티어!" 도 그대로.
- 작성자의 감탄·취향·아쉬움을 객관적 평가처럼 바꾸지 않습니다. "냉면도 맛있다는데 저는 그냥 그랬어요" 는 그대로 둡니다. "냉면 비추천"(×), "냉면은 평범했습니다"(×).
- 추천 메뉴는 작성자가 추천했거나 좋다고 적은 메뉴만, 원문에 적힌 이름 그대로. 공식 메뉴명을 추정하지 않습니다("더블" → 메뉴 칸 비움). 그냥 있다는 정도의 중립적 언급은 메뉴 칸에 넣지 않습니다.
- 단순 언급을 "대표 메뉴", "인기 메뉴", "시그니처"로 바꾸지 않습니다.
- 없는 사실을 더하지 않습니다(주소, 영업시간, 휴무일, 예약 가능 여부, 가격).
- 정리한 문장에 인용부호를 붙이지 않습니다. 원문은 상세의 작성 정보 "원문 보기"에서 볼 수 있습니다.
- 같은 문장을 목록·상세·팁 세 곳에 반복하지 않습니다. 정보마다 자리를 하나 정합니다. 구조화된 칸이 있다고 모든 자리에 출력하지 않습니다(1.2 의 겹침 규칙).

## 1. 맛집

### 1.1 저장 구조 (Supabase)

| 표 | 칸 | 뜻 |
|---|---|---|
| site_places | name(≤40) | 식당명. 지점명은 이름 안에 씁니다("마담밍 선릉점"). 별도 칸 없음 |
| | area | 표시용 지역. 값: 논현/신사 · 역삼/선릉 · 강남역 · 압구정/청담 · 삼성/대치 · 서초/교대 · 도곡/양재 · 잠실/송파 · 그 외 |
| | area_detail(≤30) | 위치 보조. 도로명 주소("역삼로 164")나 실제 동네("용산 이태원") |
| | category | 음식 종류. 고기 · 한식 · 일식 · 중식 · 양식/퓨전 · 술집/포차 · 카페/디저트 · 분식/면 |
| | price_level 1~4, price_note(≤30) | 1인 가격대(주류 제외)와 메모 |
| | map_url(≤400) | 지도 링크. 없으면 "지역 첫 단어 + 식당명"으로 카카오맵 검색 |
| | lat, lng **신규(6차)** | 좌표. 등록 폼의 장소 검색(카카오맵)이나 운영진의 위치 잡기로만 들어감. 있는 곳만 지도에 핀 |
| | closed | 영업 종료 표시(삭제 대신) |
| | author, created_at | 등록자, 등록일. 한줄평 작성자와 다른 사람일 수 있으며 화면에서도 따로 보임 |
| site_place_notes | body(≤120) | 한줄평(작성자의 평가) |
| | menu(≤40) **신규** | 추천 메뉴. 작성자가 적은 메뉴만 |
| | tip(≤120) **신규** | 방문 팁·유의사항. 작성자가 적은 것만 |
| | again | 재방문 의사 |
| | visit_date, per_person | 실제 방문일, 1인 금액(선택) |
| | author, created_at | 작성자, 작성일 |

신규 칸은 `sql/2026-09-24-content-format-1-notes.sql`(한줄평 칸·함수) → `-2-meta.sql`(소식 정리기) → `-3-posts.sql`(글 함수·형식 창) 세 쪽으로 추가합니다. 서버가 아직 이전 형식이면 화면은 한줄평 한 칸만 받고, 그 사실을 폼에 표시합니다(`site_schema_v` 조회로 판단).

좌표 칸과 위치 저장 함수 `place_set_location` 은 `sql/2026-09-25-places-location.sql` 로 추가합니다(`site_schema_v` 에 `places_location = 1`). 서버가 이 값을 주지 않거나 `assets/site-core.js` 의 `KAKAO.jsKey` 가 비어 있으면 지도·장소 검색·위치 잡기는 숨고, 목록은 그대로 동작합니다.

### 1.2 표시 항목

| 항목 | 출처 | 없을 때 |
|---|---|---|
| 식당명 | name | — (필수) |
| 지점명 | 이름 안의 "○○점" | 따로 표시하지 않음 |
| 표시용 지역 | area. "그 외"에 실제 위치(area_detail 이 주소가 아닌 것, 예 "용산 이태원")가 있으면 그 위치만 표시. "그 외 지역"은 필터 선택지에서만 | area_detail 없으면 "그 외 지역" |
| 주소 | area_detail 이 도로명·번지 꼴("…로 164", "…길 6")일 때 상세의 위치 항목에 | 생략 |
| 위치 메모 | area_detail 이 주소가 아닐 때("강남역 3번 출구 도보 5분") 상세의 위치 항목에. "그 외"면 지역 칸에 이미 썼으므로 다시 적지 않음 | 생략 |
| 음식 종류 | category | — (필수) |
| 1인 가격 | price_level → "1인 1만원 이하 / 1만원대 / 2만원대 / 3만원 이상", price_note 는 괄호. "1인 기준 · 주류 제외"는 목록 상단 결과 수 옆 한 곳에만 | 목록·상세 모두 "가격 미등록" (비교에 중요한 누락이므로 표시) |
| 추천 메뉴 | 한줄평들의 menu 를 중복 없이 모음 | 항목 생략 |
| 한줄평 | 가장 최근 한줄평의 정리본(review) 또는 원문(body) | 목록: "한줄평 없음", 상세: 한줄평 남기기 유도 |
| 방문 팁 | 한줄평들의 tip | 항목 생략 |
| 종류 아이콘 | category → `content.js` 의 CAT_ICON·CAT_COLOR. 목록 행 앞의 옅은 원, 지도 핀 색, 상세 요약 칩이 같은 것을 씀 | 모르는 종류는 기본 아이콘·보라 |
| 등록자 | site_places.author. 목록 행의 이름 아래 "등록 ○○" 칩, 상세 작성 정보에 등록일과 함께. 옮겨온 29곳은 운영진. 누르면 그 사람이 기록한 식당만 | — (필수) |
| 작성자 | 한줄평의 author. 한줄평 아래에 이름(첫 글자 원). 등록자와 별개의 사람일 수 있으며 같은 사람이어도 자리는 따로. 누르면 그 사람이 기록한 식당만 | 한줄평이 없으면 작성자 줄 없음 |
| 등록일 | site_places.created_at | 상세 작성 정보에만 |
| 방문일 | 한줄평의 visit_date | 값이 있을 때만. 등록일과 섞지 않음 |

| 식당 링크 | 상세 작성 정보의 "링크 복사" → 이 페이지의 `#place-N` 주소를 클립보드로. 들어오면 그 식당이 펼쳐짐 | 항상 있음 |

**목록 한 줄(행)의 순서** — 비교를 위한 요약

1. 종류 아이콘 + 식당명 (+ 영업 종료 / 방문 N회 / 다시 가고 싶음 N)
2. 지역 · 음식 종류
3. "등록 ○○" 칩(등록자)
4. 가격
5. 한줄평. 추천 메뉴는 한줄평 글에 안 들어 있는 메뉴가 있을 때만 앞에 "추천 메뉴" 한 줄(겹치면 한쪽만). 한줄평이 없고 메뉴만 있으면 "추천 메뉴 …" 만
6. 작성자 (· 방문일, 없으면 마지막 방문)
7. 자세히 · 지도/지도 검색

행을 펼치면 행의 한줄평 요약은 감춥니다. 바로 아래 상세에 후기 전부가 있어 같은 문장이 두 번 보이지 않게. PC 에서 지도를 열면 목록 폭이 좁아지므로 행은 모바일과 같은 두 열 배치로 바뀝니다.

**상세의 순서** — 목록에서 생략한 정보와 전체 후기

1. 요약 칩 — 종류(아이콘), 지역, 가격(메모), 방문 N회 · 마지막 방문일, 영업 종료. 기본 정보를 한 줄에 훑는 자리이며 아래 항목에서 같은 값을 다시 적지 않음
2. 추천 메뉴 — 후기 글에 없는 메뉴가 있거나 메뉴를 적은 사람이 둘 이상일 때만. 후기 한 건에 든 메뉴를 다시 적지 않음
3. 방문 후기 — 한줄평 전부(작성자, 방문일, 1인 금액, 재방문 의사). 후기 아래 "추천 메뉴 …"는 작성자가 둘 이상이고 그 후기 글에 없는 메뉴를 적었을 때만(누가 무엇을 추천했는지). 재방문 의사 비율은 2건 이상일 때만
4. 방문 팁
5. 위치와 지도 — 주소·위치 메모(있을 때), 지도에서 위치 보기(좌표가 있고 지도를 쓸 수 있을 때), 카카오맵 열기 / 카카오맵에서 검색
6. 작성 정보 — 등록자, 등록일, 원문 보기(정리본이 있을 때), 링크 복사

정보가 없는 항목은 제목째 생략합니다. "미등록"을 줄줄이 적지 않습니다(가격만 예외).

**정렬**

- 지역별 묶음(기본): 지역 목록 순서대로 "지역명 N곳" 제목 아래 묶고, 묶음 안은 최근 한줄평순. "그 외 지역"은 맨 뒤. 영업 종료는 묶음 안에서 맨 뒤.
- 최근 한줄평순: 가장 최근 한줄평의 날짜 — 방문일이 있으면 방문일, 없으면 작성일 — 가 늦은 순. 한줄평이 없는 식당은 그 뒤에 등록일 순. 영업 종료는 맨 뒤. 등록일·수정일 순이 아니므로 그렇게 부르지 않습니다.
- 방문 많은 순 / 가격 낮은 순 / 이름순.

**검색과 필터**

- 검색은 식당명·지역·주소·종류·가격 메모·등록자·한줄평(정리본·원문·메뉴·팁·작성자)의 본문 검색. 검색어가 초성으로만 되어 있으면("ㅇㅎㄱ") 식당명과 추천 메뉴의 초성과 맞춥니다.
- 필터는 지역·종류·가격·기록한 사람. 선택지마다 현재 목록 기준 개수를 붙이고 0곳은 고를 수 없게 합니다. "기록한 사람"은 등록자이거나 한줄평 작성자인 식당 — 행의 등록자 칩이나 작성자 이름을 누르는 것과 같습니다.

**지도 (카카오맵)**

- 조건: `KAKAO.jsKey` 가 있고 서버 `site_schema_v` 에 `places_location ≥ 1`. 하나라도 없으면 "지도 보기"·"위치 잡기"·장소 검색·"지도에서 위치 보기"가 전부 숨습니다. SDK 는 지도를 처음 열 때만 읽습니다(10초 안에 못 읽으면 안내).
- 지도 패널: PC(≥1080)는 목록 오른쪽 400px 고정, 모바일은 목록 위 260px 카드. 현재 조건에 맞는 식당 중 좌표 있는 곳만 종류색 핀(이름 포함). 머리에 "지도 N곳 · 위치 미지정 M곳", 아래에 종류 범례. 핀을 누르면 목록에서 그 식당이 펼쳐집니다. 켜 둔 상태는 브라우저에 기억합니다(localStorage `excer_places_map`).
- 좌표를 넣는 길은 둘. 등록 폼의 장소 검색(카카오 키워드 검색, 강남 반경 20km 우선, 5건)에서 고르면 좌표·지도 링크·주소가 함께 저장됩니다. 운영진의 위치 잡기는 좌표 없는 식당(영업 종료 제외)을 차례로 검색해 고르면 `place_set_location` 으로 저장합니다(운영진 또는 등록자 비밀번호). 주소는 비어 있을 때만 채우고, 지도 링크는 골라 준 것으로 바꿉니다.

### 1.3 기존 한줄평의 정리본

- 파일: `data/places-curated.json`. 저장소에 두고 화면이 읽습니다. 서버 데이터는 바꾸지 않습니다.
- 키: 식당명(공백 제거·소문자) + 지역(가운뎃점은 빗금으로) + 한줄평 원문(앞뒤 공백 제거, 완전 일치).
- 적용 조건: 서버의 한줄평에 menu·tip 이 없고, 원문이 정리본의 original 과 같을 때만. 작성자나 운영진이 한줄평을 수정하면 원문이 달라지므로 정리본은 자동으로 빠집니다.
- 우선순위: **작성자가 수정한 내용(서버 menu/tip/body) > 정리본 > 원문**.
- 되돌리기: 파일에서 항목을 지우면 원문으로 돌아갑니다. 몇 번을 다시 적용해도 결과가 같습니다(화면에서 병합만 하고 저장하지 않음).
- 정리 대기: 안전하게 나누기 어려운 글은 `status: "pending"` 으로 두고 원문을 그대로 보여 줍니다.
- 검증: `scratchpad/curate-check.js` 가 seed 와 대조해 매칭 건수·불일치·중복을 출력합니다.

### 2.3 목록 표시 (제목 중심)

한 행: `[유형] 제목` / 보조 한 줄: 작성자 · 날짜 · 댓글 수 · 반응 수. 유형별 보조 정보:

- 모임 모집: 모임 날짜 (D-day) · 시간 · 장소 (있는 것만). 날짜가 지나면 "지난 모임".
- 공지: 적용일이 있으면 "9월 1일부터".
- 정보: 유효 기간이 있으면 "9월 30일까지".
- 후기·자유: 본문 첫 줄 요약.

### 2.4 상세 표시 순서

- 공지: 핵심 안내 → 적용 대상 · 적용 기간 · 필요한 행동(있는 것만, 표 형태) → 상세 내용(본문)
- 모임 모집: 날짜·시간 → 장소 → 모집 인원 · 예상 비용 → 모임장 → 신청 방법 → 준비물·유의사항 → 본문 → 오픈채팅 버튼
- 모임 후기: 활동 종류 · 날짜 · 장소 → 후기 본문 → 관련 링크. 관련 링크가 이 게시판의 글(`news.html#post-N`)이면 "모임 글 보기"로 보이고 누르면 그 글이 펼쳐집니다(새 창 아님).
- 정보: 핵심 내용 → 본문 → 관련 링크 · 출처 · 유효 기간
- 모임 모집(날짜가 지난 글): 오픈채팅 참석 버튼 대신 "이 모임 후기 쓰기". 모든 글의 상세에 카카오톡 공유(못 열면 링크 복사)와 "글 접기".
- 자유: 본문

기존 글(meta 없음)은 제목과 본문만 표시합니다. 없는 항목을 만들어 채우지 않습니다.

## 3. 등록·수정 화면 규칙

- 유형을 먼저 고르면 그 유형의 항목만 보입니다. 필수는 제목·본문(모집은 날짜 권장), 나머지는 "선택" 표시.
- 제목·장소·가격·본문을 한 칸에 몰아넣지 않습니다.
- 예시는 placeholder 와 도움말로만 씁니다. 입력값으로 미리 넣지 않습니다.
- 저장 전 미리보기: 목록 행과 상세가 실제 표시대로 보입니다.
- 오류는 해당 항목 아래에 표시하고 첫 오류 항목으로 포커스를 옮깁니다. 서버 오류가 나도 입력값은 남깁니다.
- 기존 글도 같은 폼으로 수정합니다. 맛집 한줄평은 정리본이 있으면 수정 폼에 정리본을 미리 채워, 저장하면 서버 값이 됩니다(그 뒤로는 서버 값이 우선).
- 맛집 등록에는 "첫 한줄평(선택)"이 있습니다. 한줄평 폼과 같은 칸(한줄평·추천 메뉴·방문 팁·방문일·1인 금액·재방문)·같은 규칙이며, 저장은 식당을 만든 뒤 `place_note_create` 를 한 번 부릅니다(식당 쪽에 따로 저장하지 않음). 한줄평 글 없이 메뉴·팁만 적으면 저장하지 않고 한줄평을 요구합니다 — 후기 문장을 지어내지 않습니다. 정보 수정 폼에는 이 칸이 없습니다(후기 수정은 상세에서).
- 첫 한줄평에는 **작성자** 칸이 따로 있습니다(비우면 등록자 닉네임). 등록자와 한줄평 작성자는 저장도 표시도 별개입니다 — 옮겨온 29곳은 등록자가 운영진이고 한줄평 작성자는 원래 적은 사람. 미리보기에도 "등록 ○○"와 작성자가 따로 보입니다.
- 맛집 등록의 장소 검색(선택)은 식당 이름으로 카카오맵을 찾아 고르는 칸입니다. 고르면 위치 상태 줄("○○ · 주소 지우기")이 보이고, 지도 링크·주소가 비어 있으면 채워집니다. 저장 순서는 place_create → place_set_location → place_note_create. 지도를 쓸 수 없으면 칸째 숨깁니다.
- 소식의 미리 채움(7차): 지난 모임 글의 "이 모임 후기 쓰기"는 후기 폼에 종류(후기)·제목(모임명 + " 후기")·활동·날짜·장소·관련 링크(그 모임 글)를 채웁니다. 이번 주 글감 카드의 "이 글감으로 쓰기"는 종류와 제목만 채웁니다(홈의 '글 쓰러 가기'도 같은 창). 글감 목록은 `assets/content.js` 의 PROMPTS 12개를 ISO 주차로 돌아가며 씁니다 — 글감을 바꾸려면 거기서 고칩니다. 본문은 어느 쪽도 채우지 않습니다. 작성 중인 글은 이 브라우저에 임시 저장되어 창을 닫았다 열어도 남고, 저장하면 지웁니다.
- 글자 수 제한은 서버 제약(제목 100, 본문 4000, 한줄평 120, 팁 120, 메뉴 40)만 둡니다. 화면에 맞추려고 자르지 않습니다.
- AI 자동 정리 같은 실제로 없는 기능은 만들지 않습니다.

## 5. 문구 기준 (요약)

- 짧고 자연스러운 존댓말. 모든 문장을 "입니다"로 끝내지 않습니다. 멤버 후기(B)는 원문 말투를 그대로 둡니다.
- 한 정보는 한 자리에. 페이지 소개·푸터·결과 수 옆에 같은 안내를 반복하지 않습니다(가격 기준은 목록 상단 한 곳, 비밀번호 용도는 작성 폼, 커뮤니티 소개는 홈 대표 문장 하나).
- 제목은 목적이 분명한 명사나 짧은 문장. 설명은 화면에서 바로 알 수 없는 정보만.
- 버튼은 실제 행동. 성공은 완료된 사실("글을 저장했습니다."). 오류는 문제와 해결 방법.
- 쓰지 않는 표현: 근거 없는 시간 약속, 과장("완벽하게", "누구나 바로"), 감정 유도, 화면 설명 반복("여기에서 확인할 수 있습니다"), 내부 용어, 뜻이 불분명한 "완료·확인·진행".
