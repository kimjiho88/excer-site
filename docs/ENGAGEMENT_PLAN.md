# 사이트로 들어오는 길 기획 (내부 문서, 배포 제외)

2026-09-25, 20차. 오픈채팅이 메인이고 사이트는 보조다. 구성원이 사이트를 열지 않으면 쓸모가 없으므로, 채팅에서 사이트로 자연스럽게 들어오는 길을 설계한다. 현황 조사 3건, 관점별 기획 5건(채팅 순간 연결, 나를 위한 이유, 살아있는 느낌, 운영진 부담과 측정, 다른 서비스 사례), 구성원 입장과 개발 운영 입장의 평가 2건, 합친 안의 코드 대조 검증을 거쳤다.

## 1. 핵심 방향

- 채팅은 이야기하는 곳, 사이트는 남기고 찾고 정산하는 곳이다.
- 사이트로 들어오는 길은 거의 전부 누군가 채팅에 붙이는 링크다. 새 입구를 만들기보다, 이미 채팅에 오가는 링크(정산 확인, 공유 카드, 통계 카드)를 누른 자리에서 다음 기록으로 이어지게 한다.
- 중심 고리:
  1. 모임 뒤 모임장이 정산 확인 링크를 올린다(참석자 전원이 연다).
  2. 입금 완료를 누른 멤버에게 날짜가 채워진 한줄평, 후기 버튼이 보인다.
  3. 등록 직후 그 기록을 카카오톡 카드로 채팅에 올릴 수 있다.
  4. 카드를 누른 다른 멤버가 같은 고리로 들어온다.
- 살아 있다는 느낌은 실제로 쌓인 기록에서만 나오게 한다. 지어낸 숫자나 문구는 쓰지 않는다.

## 2. 들어오는 순간 지도

| 채팅 순간 | 붙이는 링크 | 붙이는 사람 | 도착하는 곳 |
|---|---|---|---|
| 신입 입장 | guide.html#cat-basics, #cat-must | 방장봇 입장 메시지 | 닉네임 양식, 처음 2주 장 |
| 신입이 첫 모임을 물을 때 | news.html 모임 모집 목록 | 방장봇 키워드 | 다가오는 모집 글 |
| 채팅방 공지 | 사이트 주소 한 줄 | 운영진(한 번 고정) | 홈 |
| 모임 공지, 전날 알림 | 모집 글 카드(날짜와 시간 표시) | 모임장 | 모집 글 상세 |
| 모임 변경, 취소, 마감 | 고친 모집 글 카드 다시 공유 | 모임장 | 모집 글 상세 |
| 당일 "어디예요?" | 식당 카드(지도 포함) | 아는 멤버 | 맛집 상세 |
| 모임 당일 밤 정산 | 정산 카드 | 모임장 | 정산 확인, 입금 뒤 한줄평과 후기 버튼 |
| 미입금 확인 | 같은 정산 카드(입금 인원만) | 모임장 | 정산 확인 |
| 모임 다음 날 | 후기 카드, 한줄평 카드 | 쓴 멤버 | 해당 글, 해당 식당 |
| "논현 저녁 어디요" | 맛집 목록 카드 | 답하는 멤버 | 필터가 걸린 맛집 목록 |
| 규칙 질문, 규칙 변경 | 이용 안내 장 링크 | 운영진, 방장봇 | 해당 장 |
| 행사, 전시, 할인 소식 | 정보 글 카드(기한 포함) | 올린 멤버 | 소식 정보 글 |
| 월 1회 통계 | report.html?report=발행번호 | 운영진 | 그 달 통계 |

## 3. 이미 반영한 것 (이번 차수, 머지 전)

- 카카오톡 공유 카드 그림: 모든 카드가 예전 홈 그림(og.jpg?v=2)을 쓰던 것을 페이지별 미리보기 그림(og-news, og-places, og-report, og-settle, og-guide, v=3)으로. 붙여 넣은 링크 미리보기와 같은 그림이 된다(site-core.js v10).
- 운영진 비밀번호 보호: 글, 댓글, 맛집, 한줄평을 등록할 때 입력한 비밀번호가 기기에 저장되어, 운영진이 운영진 비밀번호를 쓰면 기기에 남을 수 있었다. 운영진 기기에서는 비밀번호를 저장하지 않고, 통계 발행 화면에서 확인될 때 예전에 남은 운영진 비밀번호를 지운다.

## 4. 시작 전 확인 (코드 없음)

- SQL Editor에서 최근 60일의 모집 글, 후기, 한줄평 수를 센다(한줄평은 pass_hash 가 IMPORTED 인 것 제외). 모집 글이 거의 없으면 모집 글에 기대는 항목(5-6, 7-2)은 미룬다.
- 카카오톡 인앱 브라우저(iOS, Android)에서 localStorage 가 다음 방문까지 남는지 기기로 확인한다.
- 방장봇 키워드가 정확히 일치로 반응하는지, / 를 쓸 수 있는지, 개수와 글자 수 한도를 기기로 확인한다.
- 오픈채팅 캘린더 공지에 댓글을 달 수 있는지 확인한다.
- 새로 보이는 버튼 이름과 채팅용 문구를 한 표로 모아 운영자 승인을 한 번에 받는다.

## 5. 1단계: 바로 (SQL 없음)

**5-1. 등록 직후 채팅에 공유 (S)**
- 소식 글, 맛집, 한줄평을 새로 등록했을 때만 토스트 대신 목록 위에 한 줄: 카카오톡 공유, 링크 복사, 닫기. 공지 글에는 띄우지 않는다. 모집 글을 고친 뒤에도 같은 줄을 띄워 바뀐 내용을 다시 올릴 수 있게 한다.
- 모집 글 카드 설명 앞에는 D-n 대신 날짜와 시간(예: 10월 3일(토) 19:00)을 붙인다. 카드는 채팅에 남으므로 D-n 은 금방 틀린다.
- 반응 수와 댓글 수는 카드에 넣지 않는다(막 올린 글은 0).
- 계기: 채팅에 뜬 카드를 다른 멤버가 누른다. 지금은 사이트에 쓴 글을 쓴 사람 말고는 모른다.
- 만들 것: news.html 등록 처리(post_create 가 돌려주는 id 를 받아 쓴다, 지금은 버림), 1052행 토스트. places.html 1446행(새 등록일 때만), 1449, 1544행 토스트.
- 확인: 등록 3일 안에 댓글이나 반응이 붙은 글의 비율(site_comments, site_post_reactions 의 created_at 으로 SQL Editor 에서), 적용 전후 4주 비교.

**5-2. 정산 확인에서 한줄평과 후기로 (S)**
- 이 기기의 내 이름(excer_settle_myname_v1)과 같은 줄의 입금 완료를 누른 직후, 그리고 정산 완료 카드에 버튼 두 개: 한줄평 남기기(식당 검색과 한줄평 창, 방문일에 정산 날짜), 후기 쓰기(후기 종류 글쓰기, 날짜와 활동에 정산 제목. 제목이 기본값 '모임 정산'이면 비움).
- 서버 모드(1005행)와 이 기기 전용 모드(984행) 둘 다. 이름, 계좌, 정산 id 는 넘기지 않는다. 오늘보다 뒤인 날짜는 넘기지 않는다. 1인 금액은 채우지 않는다(주류와 모든 차수가 들어 있어 맛집의 1인, 주류 제외 가격과 다르다).
- 계기: 정산 카드는 참석자 전원이 여는 링크다. 정산은 120일 뒤 지워지지만 한줄평은 남는다.
- 만들 것: settle.html(978행 togglePaid, 825-830행 완료 카드), news.html 후기 해시(#write-prompt 방식), places.html openFromHash 에 한줄평 해시.
- 확인: 방문일 뒤 7일 안에 작성된 한줄평의 비율(IMPORTED 제외).

**5-3. 맛집 목록 링크 (S)**
- 필터(지역, 종류, 가격, 사람별, 정렬, 검색어)를 주소에 담고 들어오면 복원한다. 결과가 있으면 목록 머리에 목록 공유와 링크 복사. 카드 제목 "동네친구들 맛집 | 논현 한식", 설명 "N곳, 상위 3곳 이름".
- 오늘 뭐 먹지 결과에도 식당 공유 버튼(지금은 상세에만 있다).
- 계기: 채팅의 식당 질문에 답하는 멤버가 링크 한 줄을 붙인다. 채팅 답은 묻히지만 링크에는 한줄평, 가격대, 다시 가고 싶음, 지도가 있다.
- 만들 것: places.html 만. #place-N, #pick 은 그대로.

**5-4. 월간 통계 카드 (S)**
- 발행 뒤 카카오톡으로 알리기의 주소를 report.html?report=발행번호로(그림은 3장에서 og-report 로 바꿈). 문구 복사 추가: 기간, 메시지 수, 이야기한 멤버 수, 많이 나온 말 3개, 링크. 이름과 칭호는 넣지 않는다.
- 만들 것: report-admin.html notifyChat(1214-1223), report_publish 결과의 id 보관.
- 운영진: 발행 뒤 10초.

**5-5. 채팅 안에 고정 길 (코드 없음)**
- 채팅방 공지에 사이트 주소 한 줄. 방장봇 입장 메시지에 #cat-basics, #cat-must 링크. 키워드 자동응답: 정산, 맛집(places.html#pick), 규칙, 통계, 모임(모임 모집 목록).
- 정기 자동 알림은 쓰지 않는다.
- 운영진: 방장이 한 번 설정(10분).

## 6. 2단계: 내 것과 측정 (1단계 4주 뒤)

**6-1. 입장 경로 세기 (M, 새 SQL)**
- 사이트가 만드는 공유 링크와 복사 링크에 ?s= 꼬리표. 탭에 처음 들어올 때 경로와 페이지를 보내고, 주소에서는 s 값만 지운다(다른 query 와 # 뒤는 그대로: #d=, #post-N, #place-N, #pick, #write-prompt, #cat-).
- 새 함수는 이름을 따로(visit_hit_src) 두어 지금의 visit_hit() 호출과 겹치지 않게 한다. 허용 목록 밖의 값은 other. 기기 키, IP, 닉네임은 저장하지 않는다(Supabase 자체 요청 기록에는 IP 가 남는다).
- 7일 경로별 합계를 통계 발행 화면 점검 줄에.
- 운영진: SQL 한 번, 월 1회 숫자 확인.

**6-2. 활동 통계에서 내 줄 (S)**
- 한 번 찾은 이름을 이 기기에 기억하고, 그 달 명단에서 숫자 꼬리 없이 하나만 맞을 때만 내 줄을 위에 고정한다(이름이 겹치면 '엑서2'처럼 번호가 붙고 달마다 바뀐다). 겹치면 후보로만 보여 준다. 이름 가림으로 발행한 달에는 끈다.
- 멤버별 제외 체크를 발행 설정에 기억하게 먼저 고친다(지금은 다음 발행 때 잊힌다).
- report.html 은 목록(id, 기간, 발행일)만 받고 연 발행본 하나의 stats 만 받게 줄인다(직전 기간 비교는 발행본 하나 안에서 계산).
- ?m=이름 링크(남의 줄을 펼친 링크)는 사람을 지목할 수 있어 운영자 결정으로 둔다.

**6-3. 다시 왔을 때 새것 표시 (S)**
- 홈 '새 글 N' 방식을 넓힌다: 맛집 카드 '새 한줄평 N', 통계 카드 새 발행 표시(발행 id 가 바뀌었을 때만, 같은 기간 다시 발행은 제외).
- 이 기기에서 쓴 글에 댓글이 늘면 홈 소식 카드에 '내 글 새 댓글 N'. 기록이 없는 기기에는 표시하지 않는다. 탭바, 상단 바, 아이콘 숫자 배지는 달지 않는다.

**6-4. 정산에 식당 고르기 (M)**
- 계산기에 선택 칸 '식당'. 맛집 이름 검색으로 고르고 payload 에 place_id, place_name 저장. 5-2 의 한줄평 버튼이 그 식당 창을 바로 연다. SQL 필요 없음.

## 7. 3단계: 기록이 쌓인 뒤 (조건부)

2단계 뒤 주당 사이트 기록 수를 보고 정한다.

**7-1. 홈 최근 기록 넓히기 (M, 새 뷰 SQL)**
- 홈에는 이미 최근 모임 후기 1건과 최근 맛집 기록 3곳이 있다. 이것을 14일 안의 후기, 한줄평, 맛집 등록, 통계 발행 최신 6줄로 넓힌다. 댓글 본문은 싣지 않는다. 4차에서 '최근 글 5건'을 뺀 결정과 함께 운영자 승인 필요.

**7-2. 모집 글을 모임 전후 기록으로 (M)**
- 모임장용 '공지용 복사'(날짜, 시간, 장소, 비용, 준비물, 글 링크). 지난 모집 글에 연결된 후기 목록. 정산에서 모집 글로 가는 링크.
- 첫 모임을 마쳐 모임을 열 수 있게 된 멤버에게는 이용 안내 모임 열기 장과 모집 글쓰기, 모임 정산으로 가는 길을 묶어 둔다.

**7-3. 주 1회 이번 주 카드 (S)**
- 운영진 기기에서만 보이는 버튼으로 카드 한 장: "다가오는 모임 N건, 새 후기 N건, 새 한줄평 N건"(0건 항목은 빼고, 모두 0이면 버튼 숨김). 통계 발행 주에는 올리지 않는다. 3주 연속 입장이 적으면 멈춘다.

**별도 보안 항목: 운영진 비밀번호 서버 잠금**
- 지금은 통계 발행 화면의 브라우저 잠금뿐이다. 서버 잠금은 실패를 예외 대신 반환값으로 기록해야 하고, 운영진 비밀번호를 받는 함수 전부(약 16개)에 걸어야 하며, 아무나 일부러 틀려 운영진을 잠그는 문제의 처리 방법을 먼저 정해야 한다. 설계 후 운영자 승인.

## 8. 운영 루틴

- 매일: 0분.
- 모임마다: 모임장이 정산 링크를 지금처럼 올린다. 식당 고르기는 선택(10초). 미입금 확인 때는 입금 인원만 말하고 미입금자 이름은 올리지 않는다.
- 매주: 3단계 전에는 없음. 3단계 뒤 이번 주 카드 1분, 도배 글 확인 1분.
- 매월: 발행 뒤 카드와 문구 복사 10초, 경로별 숫자 확인 1분.
- 처음 한 달: 운영진이 실제 모임의 후기나 한줄평을 한 사람당 주 1건(5분). 테스트 글은 올리지 않는다.
- 운영진 이름으로 올리는 사이트 링크는 주 1회 이하.

## 9. 측정 (계정 없이 합계만)

1. 월별 한줄평 수와 후기 수(IMPORTED 제외)
2. 등록 3일 안에 댓글이나 반응이 붙은 글의 비율(created_at 기준, SQL Editor)
3. 방문일 뒤 7일 안에 작성된 한줄평의 비율
4. 통계 발행 뒤 3일의 입장 합계(site_visit_counts)
5. 채팅 링크 경로별 입장 수(6-1 이후)

## 10. 하지 않을 것

- 사이트 참석 버튼, 참석자 명단, 정원 자동 마감: 참석의 정본은 오픈채팅 캘린더다.
- 푸시, 탭바 숫자 배지, 홈 화면 설치 유도: 인앱 브라우저에서 동작하지 않고, 울리지 않는 알림은 신뢰를 깎는다.
- 지어낸 접속자 수, 시간대 인사말, 돌려 쓰는 문구: 없는 활동을 만들어 낸다.
- 칭호 수상자 이름을 홈이나 채팅 카드에 싣기, 닉네임으로 남의 기록을 모으는 프로필: 사람을 지목하고, 닉네임에 지역, 성별, 출생 연도가 들어 있다.
- 닉네임과 비밀번호로 내 기록 불러오기: 비밀번호를 대입해 볼 창구가 생긴다.
- 2개월 1회 참여 기준 충족 여부를 사이트에 표시: 사람을 지목한다.
- 정산 링크를 공개 자리에 걸거나 상세 미리보기 붙이기: 이름과 계좌가 드러난다.
- 사진 업로드: 저장소가 없고, 사진은 채팅에서 이미 잘 돈다.
- 커버 자동 전환, 커버 안에 새 줄: 운영자가 손으로 바꾸는 자리다. 공지와 다가오는 모임은 19차에서 이미 첫 섹션으로 올렸다.
- 연속 방문, 포인트, 도장판: 기기마다 끊기고 톤에 맞지 않는다.
- 링크 여러 개짜리 주간 소식 글: 공지 스팸처럼 읽힌다.

## 11. 운영자가 정할 것

1. 1단계 새 버튼(등록 뒤 공유 줄, 정산 확인의 한줄평 남기기와 후기 쓰기, 맛집 목록 공유, 오늘 뭐 먹지 공유, 통계 문구 복사)을 넣어도 되는가
2. 방장봇 입장 메시지와 키워드, 채팅방 공지에 사이트 링크를 걸어도 되는가
3. 입장 경로 집계용 새 SQL 을 실행해도 되는가
4. 통계에서 이 기기에 내 이름을 기억하고 내 줄을 위에 보여 줘도 되는가, 내 줄에 순위 숫자를 보여도 되는가, ?m= 링크를 허용하는가
5. '새 한줄평 N', '내 글 새 댓글 N' 같은 홈 알약을 허용하는가
6. 계산기에 선택 칸 '식당'을 둬도 되는가
7. 홈 최근 기록 넓히기(새 뷰 SQL)를 해도 되는가
8. 정산 확인의 후기 쓰기로 공지 없이 모인 모임의 후기가 소식에 올라와도 되는가
9. 처음 한 달 운영진이 실제 모임 후기와 한줄평을 주 1건씩 올릴 수 있는가
10. 사이트에서 쓰고 싶은 기능을 채팅 투표로 멤버에게 한 번 물어볼 것인가
