> **이 게임의 주인공은 유저가 아니라 빵집이다.** 접속할 때마다 "내 빵집이 어제보다 커졌다"를 느끼게 한다.

## 1. 확정 전제 (기획 프롬프트 §0 — 재해석 금지)

1. **플랫폼**: 모바일 웹, 카카오톡 인앱 브라우저 1순위. 세로 고정·터치·단일 페이지(`bakery.html`)
2. **스택**: HTML/CSS/JS + Vercel + Supabase. 프레임워크 없음(기존 사이트와 동일 스택)
3. **저장**: Supabase 서버 저장이 원본, localStorage는 캐시(카톡 인앱 유실 대비)
4. **과금 없음**: 에너지·프리미엄 재화·광고 게이트 없음. 순수 진행 마찰(제작 타이머·재고 상한)만 유지
5. **아트**: 이모지 + CSS + 간단 SVG. 씬은 슬롯+레이어 구조(§11)
6. **코어 플레이**: 하이브리드 — 생산 큐(Hay Day식) + 진열 재고 자동 판매(Animal Restaurant식) + 능동 조작(팁 수금·업그레이드) + 방치(오프라인에도 판매·생산)
7. **실패는 소프트 실패만**: 품절 시 손님이 조용히 떠남(기회 손실 카운트만)
8. **캐릭터 성장 금지**: 성장의 대상은 빵집뿐
9. **프레스티지/리셋 금지**: 하나의 빵집이 계속 커진다

## 2. 코어 루프

### 2.1 순간 루프 (초 단위)
메뉴 큐잉 → 제작 타이머 → 진열 → 손님 자동 구매 → 코인·팁·XP → 재큐잉

### 2.2 세션 루프 (5~10분)
접속 → **오프라인 정산 팝업** → 팁 수금 → 재고 보충 큐잉 → 업그레이드/해금 1건 이상 → 다음 목표 확인 → 이탈(큐를 가득 채우고 나감)

규칙: 어떤 세션이든 최소 1개의 의사결정이 가능해야 한다. 시뮬 기준 D1~D5 동안 매일 1~5회 업그레이드 구매가 발생함을 확인(§3.4).

### 2.3 일일 루프
일일퀘스트 3종(판매 30개 / 지정 메뉴 8개 / 업그레이드 1회) + 멤버 단골 방문 + 재고 상한 도달 전 회수 유도

### 2.4 성장 루프 (주 단위)
레벨업 → 메뉴·장비·공간 해금 → 5레벨 외형 변화 → 10레벨 확장+등급 상승 → 다음 목표

### 2.5 페이싱 목표와 검증 결과

| 목표 | 기준 | 시뮬 결과 | 판정 |
|---|---|---|---|
| 첫 판매 | 접속 3분 내 | 0.5분 | ✅ |
| Lv.2 도달 | 접속 3분 내 | 2.0분 | ✅ |
| D1 종료 | Lv.5 | Lv.5 | ✅ |

| 오프라인 상한 | 초기 4h → 후반 12h | 4.0h → 11.9h | ✅ |

### 2.6 세션-오프라인 역할 분리 (시뮬레이터가 밝힌 핵심 구조)

온라인 수요(≈5.3개/분×배수)를 생산 능력(≈10~14개/분)보다 **낮게** 설계했다.
- **세션 = 재고를 쌓는 시간**: 큐를 돌리면 판매分을 제하고도 진열대가 차오른다.
- **오프라인 = 재고가 팔리는 시간**: 15개/시×간판 배수로 소진. 진열대 상한이 곧 방치 보상 상한.
- 이 분리가 무너지면(수요>생산) 진열대가 항상 비어 방치 기둥 전체가 무너진다는 것을 시뮬 5차에서 확인 — **demandPerMin을 올릴 때는 반드시 시뮬 재검증**.

### 3.2 공식 (원본: `data/balance.json`, `data/equipment.json`)

- **경험치**: `XP_need(n) = round(24 × n^1.85)` → Lv.1→2: 24 / Lv.9→10: 1,398 / Lv.49→50: 32,142 (`levels.json xpTable`, `sim/sync-levels.js`로 생성)
- **판매**: 개당 `price` 코인 + `xp` 경험치. 팁은 판매당 14% 확률로 `max(1, round(price×0.25))`가 팁 항아리(상한 120)에 적립 → 탭 수금
- **온라인 판매 속도**: `demandPerMin × 계산대(1+0.15/Lv) × 간판(1+0.15/Lv)` (개/분, 재고 있을 때)
- **오프라인 판매 속도**: `15개/시 × 간판 배수`를 재고 메뉴의 demand 가중치로 배분. 재고 소진 시 정지
- **장비 효과** (장비당 주효과 1개):

| 장비 | 효과 | Lv.2→10 비용 |
|---|---|---|
| 오븐 🔥 | 베이킹 시간 ×0.88^(Lv-1) | 25, 45, 65, 110, 190, 330, 560, 950, 1600 |
| 진열대 🧺 | 재고 상한 60+40×(Lv-1) = 오프라인 상한 | 20, 45, 90, 180, 360, 720, 1450, 2900, 5800 |
| 계산대 🧾 | 온라인 판매 ×(1+0.15×(Lv-1)) | 15, 30, 60, 115, 220, 420, 800, 1520, 2900 |
| 간판 🪧 | 방문 속도 ×(1+0.15×(Lv-1)), 온+오프 공통 | 20, 45, 95, 190, 380, 760, 1520, 3040, 6080 |

### 3.3 페이백 규칙 (§3.2 원문 해석 확정)

원문 "2~4시간 내 회수"는 상시 플레이형 방치게임 기준이다. 엑서는 **하루 3세션(28분) + 오프라인 정산** 패턴이므로, 페이백을 "표준 하루를 업그레이드 전/후로 시뮬레이션한 하루 수익 증가분 기준 회수 시간"으로 측정한다(`sim/simulate.js estimatePayback`).
- 확정 기준: **초반(첫 8구매) 페이백 중앙값 1~6h** (측정 5.7h ✅) + **모든 구매 회수 가능(유한)** ✅
- 첫 구매들(계산대·진열대 Lv.2)은 1.9h — 원문 2~4h 감각 그대로. 후반은 길어진다(원문 "초반은 짧게, 후반은 길게")

## 8. 개인 빵집 vs 공용 빵집

| 기준 | ① 공용 단일 | ② 개인 | ③ 개인+공용 보조 |
|---|---|---|---|
| 성장 소유감 | 낮음(내 것이 아님) | **높음** | **높음** |
| 장기 접속 동기 | 무임승차 발생 | 자기 진행 | 자기 진행+이벤트 |
| 커뮤니티 참여 | 높아 보이나 갈등 위험 | 낮음 | **손님 NPC+이벤트로 보완** |
| 개발 난이도 | 동시 편집·권한 복잡 | 낮음 | 낮음(보조 공간은 P2) |
| 데이터 구조 | 공유 상태 동기화 어려움 | 유저별 문서 1개 | 유저별 문서+이벤트 테이블 |
| 운영 난이도 | 트롤링 관리 필요 | 낮음 | 중간 |
| 확장성 | 낮음 | 높음 | **높음** |
| 메이저 사례 | 없음 | 13/13종 | 다수(길드·이웃) |
| 추천 | ✗ | △ | **✓ 확정** |

**확정**: 유저마다 메인 빵집 1개 + 오픈채팅 멤버는 손님 NPC + 상호 방문은 포스트 MVP + 공용 엑서타운은 시즌/랭킹용 보조(P2). 근거는 BENCHMARK.md §3 (13종 전수 확인).

## 9. MVP 범위

### P0 (구현 완료 기준 = 이것만으로 게임 성립, Lv.1~10)
쿼터뷰 매장 씬+손님 동선(§11) · 빵집 레벨/XP바/레벨업 연출 · 등급 표시 · 생산 큐+타이머(씬 설비 탭) · 진열 재고+자동 구매 · 손님(일반+멤버, 말풍선, 착석) · 팁(카운터 탭 수금) · 코인 · 장비 4종 · **가구 상점+배치 모드(꾸미기)** · 레벨 해금 · 매장 평수 확장+외형 변화 · 오프라인 정산(재고 판매 모델+복귀 팝업) · 일일퀘스트 3종 · 서버 저장/복구 · 디버그 모드

### P1 (MVP 직후)
레시피 숙련도 UI(엔진은 P0에 포함됨) · 멤버 도감 · 특별 주문 보드 · 등급 승급 연출 강화 · 가구 확충(시즌 가구)

### P2 (포스트 MVP)
타 빵집 방문/랭킹/엑서타운 · 시즌 이벤트·선물세트 · 단체 주문 · 직원 자동화

### FTUE (첫 3분 스크립트)
접속 → 빵집 이름 짓기 → 오븐 탭 유도 → **모닝롤** 굽기(튜토리얼 한정 5초 타이머) → 진열 → 첫 손님(호스트 멤버 고정, 대사) **4개 확정 구매** → 코인·XP 획득(+보너스 10XP) → Lv.2 연출("식빵 레시피 해금!") → 일일퀘스트 안내 → 자유 플레이
*(원문의 "식빵 굽기"는 Lv.2 해금 보상 "식빵 해금!"과 모순되어 시작 메뉴 모닝롤로 조정 — §14-1)*

## 10. 기술 설계

- **상태 스키마**: 단일 JSON 문서(`bakery_state`, 필드 `v`=schema_version). 마이그레이션은 `bakery-core.js MIGRATIONS`에 버전별 함수 등록
- **DB**: `stage2/schema_bakery.sql` — `bakery_saves(uid PK, state JSONB, ver, updated_at)`, RLS 소유자 전용, CHECK 제약 최소화(검증은 앱 레이어 — 과거 CHECK 무음 거부 사고 예방)
- **시간**: 접속 시 서버 now() RPC(`bakery_now`)로 클라 시계 오프셋 보정. 실패 시 Supabase 응답 Date 헤더 → 최후 클라 시계. 모든 타이머·정산은 보정 시각 기준
- **오프라인 정산**: 접속 시 1회, `Core.offlineSettle(서버경과초)`. 클라 계산이지만 (a) last_seen은 서버 컬럼(now() 기본값)이라 기기 시계 조작 무효, (b) 상한은 진열대 재고라는 구조적 캡 존재. 서버 RPC 정산은 P1 강화 항목(T7b)
- **인증**: 익명(signInAnonymously) 시작 → 기존 stage2 카카오/구글 연결 플로우 재사용 가능. 닉네임=빵집 이름
- **성능**: 단일 rAF 루프 + 1초 논리 틱. 백그라운드 전환 시 타이머 일괄 보정(visibilitychange), 상시 setInterval 남발 금지
- **디버그 모드(P0)**: `?debug=excer` — 시간 가속 ×10/×60(가상 시계 오프셋), 코인 지급, 레벨 설정, 상태 리셋, 오프라인 정산 강제 실행
- **저장 안전장치**: 로컬 즉시 저장(디바운스) + 클라우드 45초 주기·이탈 시 저장 + 실패 시 재시도. 복구는 progressScore(레벨·누적판매) 높은 쪽 채택

## 11. 씬 / 아트 스펙 — 쿼터뷰 매장 (아이러브커피식 전면 개편, §14-6)

- **씬 = 쿼터뷰(아이소메트릭) 매장 그 자체가 게임 화면**. 2:1 다이아몬드 타일(56×28px) 바닥 + 스큐 벽 2면 + 좌측 벽 문. CSS clip-path/skew만 사용(별도 일러스트 없음)
- **매장 평수** = `levels.json roomTable`: Lv.1 7×5 → Lv.10 8×6 → Lv.20 9×7 → Lv.30 10×8 타일 (10레벨 확장 규칙 = 평수 확장)
- **고정 설비**(levels.json slots): 오븐(벽면)·커피바(Lv.3, 🫖→Lv.7 ☕ 교체)·진열대·카운터 — 씬에서 직접 탭해 조작(오븐 탭=베이킹 시트, 카운터 탭=팁 수금). 잠금 설비는 레벨 도달 시 등장
- **가구 배치(꾸미기)**: furniture.json 아이템을 상점에서 구매 → 꾸미기 모드에서 원하는 타일에 배치/회수. 좌석 가구는 손님이 실제로 앉는다. 배치 상태는 `state.layout`
- **직원 연출**: 제빵사(오븐 가동 중 애니메이션)·캐셔(카운터). 능력치는 장비 레벨이 대변(별도 직원 성장 없음 — §0.8 캐릭터 성장 금지 준수)
- **손님 동선**(판매 이벤트에 동기화된 연출, 경제는 엔진): 문 입장 → 카운터 줄서기 → 주문 말풍선 → 구매(멤버는 닉네임+대사) → 빈 좌석에 착석해 먹기 or 포장 퇴장 → 품절이면 잠시 기다리다 조용히 퇴장(소프트 실패)
- 등급별 `grade-N` 테마 클래스: 벽·바닥 색 교체. 기계 검수(레벨업 가시 변화)는 sync-levels.js

## 14. 확정 과정의 조정 사항 (근거 로그)

1. **FTUE 첫 베이킹 = 모닝롤**: 원문 §9는 "식빵 굽기" 후 "Lv.2 식빵 해금!" — 튜토리얼에서 구운 메뉴가 다시 해금되는 모순. 시작 메뉴 모닝롤 신설로 해소(Lv.2 식빵 해금의 감격 유지)
2. **Lv.10 등급명 = 인기 베이커리**: 원문 §9의 "카페형 베이커리"는 §5.2 등급 사다리에 없는 명칭 → §5.2 사다리로 통일
3. **페이백 규칙 재해석**: §3.3 참조 — 세션형 플레이 패턴 기준으로 측정 방법 정의(초반 중앙값 5.7h, 첫 구매 1.9h)
4. **D7 페이싱**: Lv.10을 D4에 조기 달성(목표 D7). MVP 콘텐츠 끝(Lv.10)에 빨리 닿는 것은 커뮤니티 초기 화제성에 유리하다고 판단해 허용 밴드(D7에 Lv.10~11)로 확정. Lv.11+ 콘텐츠(P1) 출시 전까지 자연 감속 구간이 완충 역할
5. **온라인 수요 < 생산 능력** 원칙 신설(§2.6): 방치 기둥 성립의 전제 조건으로 시뮬이 입증
6. **아이러브커피식 전면 개편 (운영자 지시, schema v2)**: 카드형 탭 UI를 폐기하고 쿼터뷰 매장 씬(§11)으로 전면 교체 — 걸어 들어오는 손님 동선, 씬 내 설비 직접 조작, 가구 상점·배치 모드(인테리어 P1→MVP 승격), 직원 연출 추가. **경제·생산·정산 엔진은 시뮬 검증본을 그대로 유지**(아이러브커피의 '머신 예약 생산+재고 판매' 구조와 동일 모델이라 재검증 불필요, 인테리어 팁 보너스만 추가 후 시뮬 재통과 확인). 기존 세이브는 MIGRATIONS[2]로 자동 이전. 가구 상점은 §3.5에서 지적된 후반 코인 잉여의 신규 싱크 역할
