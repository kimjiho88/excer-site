# 카카오 로그인 준비 (운영자 설정)

카카오 로그인 코드를 넣기 전에 운영자가 두 화면에서 설정하고, 숨은 확인 화면으로 시험합니다. 메뉴 이름은 화면 개편에 따라 조금 다를 수 있습니다.

비밀 값(클라이언트 시크릿)은 Supabase 설정 칸에만 붙여 넣습니다. 채팅, 저장소, 소식 글에는 올리지 않습니다.

## 넣을 값

| 칸 | 값 |
|---|---|
| 리다이렉트 URI(카카오) | `https://drggzlnzwvkhtalvkqyo.supabase.co/auth/v1/callback` |
| Redirect URLs(Supabase) | `https://excer-site.vercel.app/**` |
| 개인정보 처리방침(카카오에 칸이 있으면) | `https://excer-site.vercel.app/privacy.html` |
| 설정 확인 화면 | `https://excer-site.vercel.app/kakao-check.html` |

## 1. 카카오 디벨로퍼스(developers.kakao.com)

지도와 공유에 쓰는 앱(excer)에 카카오 로그인을 켭니다. 새 앱은 만들지 않습니다.

1. 내 애플리케이션에서 **excer** 를 엽니다.
2. **카카오 로그인**: 사용 설정을 **ON**.
3. 카카오 로그인의 **동의항목**:
   - 닉네임(`profile_nickname`): **선택 동의**. 동의 목적은 '모임 참석 본인 확인'. 필수 동의는 카카오 검수가 필요할 수 있어 선택으로 둡니다.
   - 프로필 사진, 카카오계정(이메일): **사용 안 함**(받지 않음).
4. **앱 > 플랫폼 키**(화면에 따라 앱 키)에서 **REST API 키**를 엽니다. 개편 전 화면이면 아래 두 칸이 카카오 로그인 메뉴 안에 있습니다.
   - **리다이렉트 URI**: 위의 값 하나만 등록합니다. 글자가 하나라도 다르면 로그인할 때 KOE006 오류가 납니다.
   - **클라이언트 시크릿**: 코드를 확인하고(없으면 만들기) 사용 상태로 둡니다.
5. REST API 키 값과 클라이언트 시크릿 코드는 2단계의 Supabase 칸에 붙여 넣기만 합니다.
6. 개인정보 처리방침 URL 칸이 있으면 위의 값을 넣습니다.

## 2. Supabase 대시보드

1. **Authentication > Sign In / Providers > Kakao** 를 엽니다.
2. 이미 켜져 있으면 **REST API Key** 가 1단계 excer 앱의 REST API 키와 같은지 봅니다. 다르면 바꾸지 말고 개발 세션에 알립니다(바꾸면 이미 카카오로 로그인한 계정이 이어지지 않습니다).
3. 꺼져 있으면 **Enable** 을 켜고 **REST API Key** 에 REST API 키, **Client Secret Code** 에 클라이언트 시크릿을 넣습니다.
4. **Allow users without an email** 을 켭니다. 이메일을 받지 않으므로 이것이 꺼져 있으면 로그인이 막힙니다(예전에 카카오 로그인이 안 된 가장 유력한 원인).
5. **Save**.
6. 같은 Sign In / Providers 화면의 **Allow new users to sign up** 이 켜져 있는지 봅니다. 꺼져 있으면 처음 로그인하는 사람이 막힙니다.
7. **Authentication > URL Configuration**: Redirect URLs 에 `https://excer-site.vercel.app/**` 가 있는지 보고 없으면 더합니다. Site URL 은 그대로 둡니다.

## 3. 설정 확인(반영 전 시험)

메뉴에 없는 운영진 전용 화면입니다. 사이트의 글, 참석, 운영 자료는 바뀌지 않고, 다른 화면의 로그인과도 섞이지 않습니다.

1. 폰에서 `https://excer-site.vercel.app/kakao-check.html` 을 엽니다.
2. **카카오 로그인**을 누르고, 카카오 동의 화면에 닉네임만 보이는지 봅니다.
3. 돌아와서 '설정이 맞습니다'가 나오면 끝입니다. 오류가 나오면 화면의 '고칠 곳'대로 고친 뒤 다시 합니다.
4. 끝나면 **로그아웃**을 누릅니다. 이 시험으로 Supabase 에 본인의 로그인 정보가 하나 생기며, 필요 없으면 Authentication > Users 에서 지웁니다.

막히면

- 카카오 화면에 KOE006: 리다이렉트 URI 글자가 다릅니다.
- 카카오 화면에 KOE205 와 카카오계정(이메일): 카카오가 이메일 동의항목을 비즈 앱에만 열어 주는 경우입니다. 카카오 디벨로퍼스에서 개인 개발자 비즈 앱으로 전환한 뒤 이메일을 선택 동의로 켜고 개발 세션에 알립니다(처리방침에 이메일(선택)을 더해야 합니다).
- 카카오 화면에 KOE205 와 다른 항목: 화면에 적힌 항목 이름을 개발 세션에 알립니다.
- 로그인 뒤 확인 화면이 아니라 홈으로 가면: Supabase Redirect URLs 에 위의 값이 없습니다.

## 4. 같이 확인할 것

- **옛 방문 기록 정리**: `sql/2026-10-16-privacy-cleanup.sql` 을 아직 안 돌렸으면 `sql/backup.sql` 다음에 돌립니다(sql/README.md).

## 5. 끝나면

- '설정 끝' 과 확인 화면의 결과(설정이 맞습니다, 또는 오류 문장)만 알려 주세요. 키나 비밀 값은 보내지 않습니다. 2단계 2에서 키가 달랐으면 그것도 알려 주세요.

## 6. 반영 전에 정할 것

- **닉네임 묶기 확인 방식**: 먼저 묶은 사람으로 두고 운영진이 목록을 보며 다툼을 푸는 방식, 또는 운영진이 승인해야 묶이는 방식.
- **로그인 필수 시점**: 처음 얼마 동안 기존 비밀번호 방식과 함께 쓸지.
- **방을 나간 사람의 묶기**: 언제 풀지(예: 나가고 30일 뒤 자동).
- **로그인 단추 옆 안내 한 줄**: 받는 정보와 처리방침 링크를 보일지.

## 그다음 순서

1. 서버: 카카오 계정과 채팅방 닉네임을 하나씩 묶는 표와 함수. 참석, 취소, 모임 올리기는 서버가 로그인한 계정으로 판단(화면이 보낸 닉네임을 믿지 않음).
2. 소식 화면: '카카오 로그인' 단추(카카오 디자인 가이드의 노란 단추)와 닉네임 고르기, 로그아웃, 묶기 풀기. 로그인 저장은 다른 화면과 따로.
3. 운영 화면: 묶기 목록, 풀기와 바꾸기, 같은 닉네임을 둘이 고른 경우, 탈퇴 요청 시 묶기와 로그인 정보 지우기.
4. 처리방침에 카카오 로그인 항목(카카오 회원번호, 카카오 닉네임, 묶은 닉네임과 일시, 로그인 기록, 보유 기간)과 브라우저 저장소의 로그인 상태를 더함.
5. 기능은 먼저 운영진에게만 보이게 켜서 실제 소식 화면에서 시험합니다. 문제가 없으면 운영진이 소식 공지로 알리고, 7일 뒤 모두에게 켭니다(처리방침의 변경 고지).
6. 켜진 뒤 폰(카카오톡 안 브라우저)에서 한 번 참석해 봅니다.

## 지킬 것

- 클라이언트 시크릿과 운영진 비밀번호는 채팅, 저장소, 소식 글에 올리지 않습니다.
- 리다이렉트 URI 는 위의 값 하나만 둡니다.
- 동의항목은 닉네임 하나로 시작합니다. 쓰지 않는 항목은 받지 않습니다.
